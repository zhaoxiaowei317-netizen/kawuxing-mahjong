# 公开信息终局收益推演

本模块尝试把出牌依据从“后续是否更容易成牌”推进到“最终可能多赢多少分”。它是搜索策略，没有新增神经网络参数训练，也没有替换游戏默认 H0。

## 怎样推演

先让 H0 和两步牌效搜索分别给出一个出牌。当两者不同，且当前状态受支持时，最多在这一手考虑一次替代选择。胡、碰、杠、亮倒和已经亮倒后的动作仍遵循 H0。

未知牌按 `4 − 当前公开可见张数` 得到。其中既有对手暗手，也有未摸牌墙。每个假设世界把这些牌不放回随机分配，保持自己的手牌、所有公开牌、亮倒听口、手牌张数及牌墙长度不变。程序会检查：重新生成的公开观测与实际输入完全一致，根节点合法动作也完全一致。

两个候选在同一个世界中各自打到终局，各分支独立克隆状态。正式引擎计算胡分、杠分和查叫；对手提前胡牌会立即终止该分支。然后比较两个候选的配对平均净收益，只有替代出牌更高时才采用，打平保留 H0。

每手最多进行一次这种选择，后续自己的动作回到 H0。因此实验检验的是这一次局部改进，没有把“后续也继续收益搜索”混在一起。

## 三个固定候选

| 候选 | 作用 |
| --- | --- |
| `proposal-once` | 使用同样的候选和触发条件，直接采用一次前瞻出牌，作为对照 |
| `ev-H0` | 假设后续两家都是 H0，按最终净收益决定是否采用前瞻出牌 |
| `ev-mixed` | 一半世界假设两家 H0，另一半假设 H0 加 greedy-speed，后者在两个座位间平衡 |

三者都只比较与 H0 同向听数的候选。默认每次收益筛选采样 16 个世界，共完成 32 个假设分支。实验使用平均净收益差，不把假设样本的均值当作实战证明；程序还记录配对标准误，用于理解采样噪声。

## 已知限制

未知牌分配是根据当前公开数量的均匀抽样，没有根据对手之前为何碰牌、亮倒或出牌更新概率。对手未公开的过胡、过碰、补杠禁令按空处理，所以假设状态可能与真实历史不同。亮倒对手仍有隐藏保留刻子时，本版明确回退 H0。

推演中对手使用的是固定的简单策略，不能代表所有真人打法。自己的手牌和未来合法动作来自各假设分支当时的公开观测，实际暗手与真实牌墙顺序没有传给决策函数。

16 个世界仍可能有明显噪声。该机制先验证收益推演、对手提前终局和多种对手模型能否带来价值；没有据此承诺提高胜率或真人段位。

## 固定预算实验

```sh
node ai/public-rollout/study.mjs --out ai-runs/public-net-score-new
```

输出必须为新目录。首局之前写入规则及源码哈希、配置、种子、预算和停止规则。默认三个候选各有 960 局开发评测，按连续 16 手的净收益差选择；没有正的开发均值则选回 H0 并停止。

若有候选胜出，使用新种子对 H0 做 3,456 局独立评测；若选中收益筛选策略，还会另用新种子对 `proposal-once` 做 3,456 局对照，检验收益筛选本身。最多 9,792 局实际评测，不根据中途成绩追加预算。

主指标是连续 16 手的底分净收益差，两个对手组合为 H0/H0 与 H0/greedy-speed。六种座位排列、真实轮庄、整组配对 bootstrap 与现有平台一致。独立单局为辅助指标，开发与封闭结果不合并。

## 如何复核

实际评测与假设推演分别计数。每局实际牌谱完整保存；每次提案另保存当时的公开观测、合法动作、策略配置、假设种子及分支结算。封闭评测记录只用于验收和审计，不能混入训练集。

```sh
node ai/public-rollout/verify.mjs --out ai-runs/public-net-score-new
```

复核工具重新按种子发牌，核对实际前一局赢家及积分，完整重放所有实际动作和结算；把每条提案记录对回实际牌局当时的公开观测；重算分组收益和区间。假设推演按“测试阶段 × 对手组合 × 策略”分层抽样完整重算，报告明确列出数量，不把抽样重算声称为全部推演重算。

实现位于 `ai/public-rollout/`，测试位于 `tests/ai-public-rollout*.test.mjs`。已完成实验的源码必须保持哈希不变，后续新搜索或训练模块使用新版本文件。

## 赛后反事实诊断

```sh
node ai/public-rollout/diagnose.mjs --out ai-runs/public-net-score-new
```

这是与决策代码隔离的离线审计，策略、采样器和比赛程序均不导入它。审计程序在比赛结束后读取记录中的完整局面，在相同真实暗手和牌墙下分别采用两种出牌，再按实际对手打法打到结束。因为比赛中每手最多改变一次动作、随后回到 H0，审计中实际选择的分支必须精确重现记录的得分，否则报错。

诊断能列出：提案若始终采用会怎样，收益筛选接受或拒绝后会怎样，以及预估收益与这一次实现收益是否一致。每个真实局面仍只对应一次具体运气，不能把实现收益当作真实条件期望；不同策略遇到的局面也不能跨行直接排名。

审计结果只输出分数及公开的对局定位，不导出暗手给决策函数，也不把这些开发或封闭记录当作训练集。它的用途是找问题来源，不能代替正式的整套策略对战。

## 分阶段运行与恢复

开发筛选完成、`selection.json` 已保存后，可以把计划中尚未开始的独立比较单独运行，便于并行利用本机 CPU：

```sh
node ai/public-rollout/finish.mjs evaluate --out ai-runs/public-net-score-new --against proposal-once
```

只能运行原计划声明的比较，候选、配置、种子和预算均从计划读取。已有阶段目录不能覆盖。若原来的顺序驱动随后遇到该目录，会保护性停止，保留已完成和正在运行的比较；不会重复生成该批牌局。

等所有计划内比较都生成 `report.json` 后，汇总而不重新训练、评测或选模：

```sh
node ai/public-rollout/finish.mjs finish --out ai-runs/public-net-score-new
```

汇总器逐项检查计划、配置、预算、源文件、牌谱哈希与重算的统计，只接受完整阶段；已有总报告也不能覆盖。`orchestration.json` 记录各阶段报告哈希。完整动作和推演审计仍使用前面的 `verify.mjs`。
