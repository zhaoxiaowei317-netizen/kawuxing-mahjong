# AI 训练机制与运行指南

日期：2026-10-17。规则 `xiaogan-1.0`，训练协议 `kwx-ppo-mc-1`。

训练闭环已搭建并实跑：H0 模仿初始化 → 当前模型采样 → PPO 参数更新 → 历史对手池 → 检查点 → 独立开发评测 → 保存后续训。当前交付是可复现的 CPU 参考实现与机制验证模型，牌技仍须经更大规模独立实验验证。

## 直接运行

只需项目现有 Node.js 24 和依赖，不需要额外安装 Python、PyTorch、GPU 驱动或下载外部权重。

先跑较小的流程验证：

```sh
npm run ai:train -- --config ai/configs/smoke.json --iterations 2 --out .tmp/ai-training/run-001
```

启动较长的单局训练，或以完整 16 局为一个训练 episode：

```sh
npm run ai:train -- --config ai/configs/cpu-small.json --iterations 8 --out .tmp/ai-training/run-002
npm run ai:train -- --config ai/configs/cpu-table.json --iterations 8 --out .tmp/ai-training/table-001
```

`--iterations` 是目标 PPO 迭代号。每轮先完成采样，再更新网络；不是麻将局数。`episodesPerIteration × trainingHands` 是每轮实际麻将手数，默认前者 24、后者 1；整桌配置为每轮 4 桌 × 16 局。模仿阶段的 `bcEpisodes` 另计。

输出目录必须为空或不存在。程序不会覆盖旧实验，不会更换正在游戏中的电脑，也不接触正式房间与浏览器存档。

## 保存与继续训练

每次模仿完成及 PPO 迭代结束，保存完整检查点。查看 `latest.json` 找到文件，也可直接指定已知路径：

```sh
npm run ai:train -- --resume .tmp/ai-training/run-001/checkpoints/iteration-00002.json --iterations 8 --out .tmp/ai-training/run-003
```

续训读取原配置、网络参数、Adam 一二阶矩与偏差修正、计数器、开发评测记录及历史对手。模仿阶段不重复。停止目标可增大；精确续训不允许改变学习率、种子或其他训练配置。需要调参时另起实验。

同一 Node 版本与源码下，连续训练到第 2 轮，和训练到第 1 轮、保存后恢复到第 2 轮，得到完全相同的网络参数、Adam 状态和训练指标，已有端到端测试验证。随机流由根种子、阶段、迭代、桌号、局号、座位及策略身份派生，不依赖进程当前随机状态。

中断发生在一轮中间时，从上一完整检查点重做该轮；未完成的样本和更新不会当作完整迭代提交。文件先写临时文件再改名，检查点不覆盖，`latest.json` 仅指向完整检查点。恢复始终写入新目录，保留原实验。

**续训需要保留原实验中的历史对手文件。** 检查点内记录其路径与 SHA-256，文件缺失或被修改会拒绝续训；单独复制一个 checkpoint 足以推理，但不能保证独立续训。整体归档实验目录时也应保留它引用的父实验。当前使用绝对路径，跨机器迁移还需显式迁移这些引用，尚未提供自动打包功能。

## 使用模型参加评测

```sh
npm run ai:eval -- --candidate-model .tmp/ai-training/run-001/checkpoints/iteration-00002.json --incumbent H0 --groups 8 --session-groups 2 --out .tmp/ai-evaluation/model-001
```

两份模型可分别用 `--candidate-model` 和 `--incumbent-model`。模型身份由检查点文件 SHA-256 派生；报告记录模型、编码、规则与代码版本、训练步数、迭代号。开始和结束检查文件未变，规则、编码或推理依赖不匹配则拒绝加载。

训练时根据合法动作概率随机采样；开发评测默认选择概率最大的合法动作，报告明确记录此推理方式。两者不是完全相同的行动分布；比较多个版本时须保持推理方式一致。环境始终提供合法动作遮罩并再次验证执行。

训练内按 `evalEvery` 定期运行开发集，对手和配对协议沿用 M0，完整指标写入 `evaluations/`。开发评测的牌局不进入训练样本，也不据此自动升级游戏 AI。当前没有自动“晋级冠军”功能；正式晋级仍按[评测方案](AI牌技提升与评测方案.md)采用足够独立组和新的封存批次。

## 已实现的学习方法

输入采用 1085 维公开观测编码、相对座位和 88 个语义动作，精确布局见[训练编码与动作协议](训练编码与动作协议.md)。不输入审计种子、真实牌墙、对手暗手、亮倒预留暗坎身份或未公开响应。

网络是一层 tanh 共享隐层，加策略头和价值头。隐层大小可配置，CPU 配置默认 32；所有参数、梯度和 Adam 状态使用 Float64。参数随机初始化，没有外部预训练权重。

模仿阶段从 H0 的完整合法对局采集三家各自可见的观测与动作，优化合法动作上的交叉熵。它用于初始化，不以模仿准确率证明超越 H0。

PPO 使用冻结采样策略生成整批样本，之后进行多轮小批量更新，包含 clipped surrogate、熵项、价值均方误差、Adam 和全局梯度范数裁剪。核心梯度已用有限差分检查，正负优势的裁剪分支、熵方向和共享价值梯度均有专门测试。方法来源是 [PPO 原论文](https://arxiv.org/abs/1707.06347)，这不是 Mortal 的算法复现。

当前采用终局 Monte Carlo 优势：`advantage = 实际终局净分 / rewardScale − 采样时价值预测`，默认 `rewardScale=16`、底分固定为 1；按整批样本标准化优势。没有把胡牌率、向听下降或做大牌当成奖励。`trainingHands=16` 时回报为该桌 16 局的总净分，真实结果决定下一局庄家，累计分和局号随之进入观测。每一局的胡分、杠分和查叫只进入总收益一次。

此版本未使用 GAE、截断 bootstrap、搜索或奖励塑形。完整终局回报实现较直接，但方差可能较大；后续算法改进应通过同条件评测验证。

## 自博弈与历史对手

默认约一半训练桌由当前模型的三个独立策略随机流互打；其余桌轮换学习席位，另外两家分别从 H0、简单速度策略和近期历史模型中等概率抽取。两家可抽到同一版本，但各自有独立随机流。

每批采样结束前不更新当前模型。只将当前模型自己的行动加入 PPO；H0、简单策略和历史模型的动作不会冒充当前策略样本。每轮结束保存历史模型，活跃池默认保留最近 4 份，旧文件仍归档。它是初始历史池机制，尚未实现自动寻找专家或复杂联盟调度。

三份同模型互打时，总得分因零和可能为零，这是正常现象，不能据此判断训练没有进步或已经变强。训练奖励、loss 与真实牌技是不同指标。

## 输出内容和接口

| 路径 | 内容 |
| --- | --- |
| `run.json` | 配置、目标迭代、父检查点、源码哈希 |
| `checkpoints/iteration-xxxxx.json` | 完整网络、Adam、计数器、历史池和开发记录 |
| `league/model-xxxxx.json` | 固定历史对手快照 |
| `latest.json` | 最新完整检查点路径与校验和 |
| `metrics.json` | 模仿及每轮 PPO 的 loss、熵、KL、裁剪、梯度、实际采样数与参数哈希 |
| `evaluations/` | 独立开发对战的分组原始记录与区间 |
| `summary.json` | 完成本次运行的计数、耗时、最终模型及评测定位 |
| `failure.json` | 失败原因和上一完整检查点；训练对局依靠种子重跑定位 |

实现位于 `ai/training/`：`encoding`、`network`、`policy`、`collector`、`checkpoint`、`trainer`。`ai/train.mjs` 为命令行入口，`ai/configs/` 提供三份配置。训练采样不保存每一步全信息牌谱，开发 CLI 可保存全量审计重放；这能减少训练存储，但异常定位需要按记录版本和种子重跑。

## 验证与后续

初始机制验收时为 **150 项测试通过**；加入同权重实验分支、动作诊断、完整对照和自身局面纠错流程后为 **156 项测试通过**。覆盖原规则、信息边界、动作编码、真实梯度、优化学习方向、奖励归属、16 局训练轮庄、完整保存恢复与模型 CLI 对战重放。初始运行见[训练机制验收记录](reports/training-mechanism-2026-10-17/验收记录.md)，后续实验见[首轮对照实验](AI首轮对照实验.md)与[自身局面纠错实验](模型自身局面纠错实验.md)。

当前后端是单进程 CPU 参考实现，没有 GPU/张量批处理、并行训练 actor 或高吞吐神经推理。M0 的多线程吞吐数字不能直接作为训练速度。后续可用兼容的张量后端替换计算实现，但必须保持编码、合法动作和损失测试一致，并重新记录版本。

已提供 `ai:experiment` 进行多个独立训练种子的模仿、自博弈和混合对手比较，并固定候选后运行独立验收。`ai:train` 新增 `--initialize-from`，用于复制权重、重置优化器开展新实验，与精确 `--resume` 严格区分。具体预算、选择规则、产物和限制见[首轮对照实验](AI首轮对照实验.md)。模型不强也保留报告，不因训练流程跑通就宣称已经得到高手。
