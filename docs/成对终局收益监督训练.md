# 成对终局收益监督训练

这套机制训练 AI 判断：遇到两种有争议的出牌时，换一种出牌是否值得。它用新生成的训练牌局，把两个选择分别打到正式结算，学习最终净分差。模型实际打牌时只能使用自己的牌和公开信息。

所有牌局由本机正式规则引擎生成，计算使用本地 CPU。这里“实际牌局状态”指当手模拟对局已经发出的牌和剩余牌墙；它与事先随机另造的未知牌分布假设分开记录。

## 生成学习目标

每手指定一个训练座位，其他两家按事先确定的 H0/H0 或 H0/greedy-speed 策略打牌，座位和组合轮换。训练座位先按 H0 打；第一次遇到 H0 与两次摸牌前瞻给出不同出牌时，复制当时的完整牌局，分别执行两个动作。之后训练座位均使用 H0，其他两家的策略也保持一致，直至正式引擎结算。

标签为“替代出牌的终局净分 − H0 出牌的终局净分”，按底分归一化，包含胡牌、杠分和流局结算。两个分支共用当时真实的暗牌和剩余牌墙，隔离出牌差异。每个牌局只采一个决策点；没有争议点的牌局也计入采集手数。

完整暗牌仅用于离线计算终局奖励。模型输入、选牌接口均接收公开观测，模型不会得到环境种子、完整牌墙、对手真实暗手、对手策略名称或最终奖励。牌谱中保留可供审计的种子和动作前缀，但训练器只从每行读取 `features` 和 `gain`。

一次具体牌局的收益差很受运气影响。模型要从不同训练牌局学习公开局面与平均收益的关系；某个标签为正，不代表该出牌在所有暗牌分布下都更好。

## 模型与使用方式

输入是 64 个公开特征，包括两种出牌的向听、进张和两次摸牌发展，自己的牌形，以及两家公开的牌河、副露、亮倒等信息。比较带正则的线性模型和三个不同初始值的小型单隐层网络。三个网络使用同一批数据，不能把数据量乘三。

网络初始输出严格为零，对应保留 H0。训练只做收益回归；复用网络中的价值输出和 Adam 优化器，策略输出梯度严格为零。虽然底层复用名为 `ppoUpdate` 的接口，本实验没有进行 PPO 策略训练。

训练目标按 16 底分缩放，不裁剪真实标签。验证集只选择均方误差最低的轮次，包括尚未训练的第 0 轮；误差相同时保留较早轮次。训练集和验证集不包含旧评测数据，也不包含本次开发或封闭评测牌局。

实际选牌时，每手至多考虑一次替代出牌。预测收益大于零才采用，否则继续用 H0；之后本手其余动作仍使用 H0。这个限制让实际策略与训练分支的后续打法一致，也限制了这一轮能改进的范围。

提案入口沿用上轮前瞻的限制：保留胡牌、杠牌、亮倒选择和已经听牌的 H0 决策，只比较同向听的普通出牌；牌墙范围受限，亮倒对手仍藏有保留刻子时也会回退 H0。这轮没有训练这些入口之外的选择。

## 独立衡量牌技

实验在生成第一手数据前写入计划、预算、源码哈希和各阶段独立种子。四个模型完成固定开发评测后，只选开发连续对局净分差最高且为正的一个；都不为正时保留 H0。候选随后使用新种子，与 H0 和“直接采用一次前瞻出牌”分别比较，区分整体牌技与筛选器本身的作用。

每组用相同发牌随机种子、六种座位排列、新旧两个版本，连续对局保留实际轮庄。主指标是每百手终局净分差，对手组合等权，以整个配对组重采样计算区间。独立单局和分对手结果辅助解释，不能用开发领先替代封闭验收，也不能只挑有利的子组汇报。

训练牌局、验证牌局、实际评测、两种出牌的离线分支分别计数。重复训练轮次和不同网络初始值不新增独立牌局。模型不会自动替换游戏电脑；实验默认策略仍为 H0。

## 使用

在项目根目录运行，输出目录必须是新目录：

```powershell
node ai/paired-value/study.mjs ai-runs/paired-value-001
node ai/paired-value/verify.mjs ai-runs/paired-value-001
```

大规模运行也可用 `node ai/paired-value/verify-parallel.mjs ai-runs/paired-value-001` 分配四个本地 CPU 进程复用相同审计函数；它还会核对全局计划、模型和选择规则，并记录审计驱动源码哈希。串行与并行审计输出使用同一文件名，均拒绝覆盖，按需选择一种运行。

默认采集 6,000 手训练、1,200 手验证，四个本地 CPU 进程使用不重叠的手号；分片合并后的牌局序列与串行采集一致。训练三个 8 隐单元网络，每个 20 轮，另拟合一个线性模型。开发评测共 3,456 局；若选出候选，两项封闭对照各 3,456 局，最大实际评测预算 10,368 局。

`trainGain` 支持从包含 Adam 状态的检查点精确续训，严格检查源码、数据哈希、种子及训练配置；不能覆盖已有检查点。完整实验驱动会拒绝覆盖已有目录，避免意外重用旧评测结果。若驱动被中断，应检查已完成阶段，不能通过重复运行来挑选更好的随机结果。

如果仅采集子进程启动失败，应先使用计划中原种子、原全局手号补齐缺失分片，所有分片完整后可运行 `node ai/paired-value/recover.mjs 原实验目录`。它核对分片范围、数据哈希与冻结源码，复用已完成模型和评测；不创建新种子，不覆盖完整阶段，不自动重打不完整的评测。系统若在并发创建父目录时拒绝某个子进程，保持其原计划参数补跑即可，无需重抽整批数据。

审计会从种子重新发牌，核对每个已保存训练决策点的 H0 前缀、首次提案、公开特征和两个终局标签；还会重算所有网络轮次和线性拟合，核对验证选择。实际评测全部保存完整牌谱并重放，另行审计重新发牌、轮庄、每次策略动作、决策记录、收益汇总和统计结果。未产生决策点的采集牌局不保存完整牌谱，审计并不逐手重跑这些牌局。

## 当前边界

这仍是局部决策学习：输入是少量手工特征，每手只可能更改一次出牌，碰、杠、亮倒与后续决策继续沿用 H0。训练后续对手只有两种预设类型，独立开局采集与连续轮庄评测也存在分布差异。因此即使验收分差为正，也只能说明本次固定规则和对手组合下的证据，不能宣称已达到真人高手或最强麻将水平。

这轮的价值是把“凭牌形猜哪个动作更好”推进为“从正式终局的实际得失学习”，同时保留可复核的独立验收。是否提升，以实际封闭结果为准。
