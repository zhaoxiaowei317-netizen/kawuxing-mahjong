# 两步公开牌效搜索

本轮尝试直接增加出牌决策的前瞻深度，不新增神经网络训练，也不覆盖现有检查点。规则、公开观测、H0 与旧模型推理文件保持原有哈希。

## 搜索计算什么

H0 优先考虑亮倒、向听数和当前有效进张。新策略在尚未听牌时，再问一个具体问题：摸进一张后，能否通过出牌让下一张继续推进？

对每个候选出牌，枚举公开未知的第一张牌，按剩余张数加权。摸到后，枚举下一次可打的安全牌，再计算第二摸的有效张数。以这两次抽取能否使向听数降低两级为目标：一向听看两摸内成牌，二向听看两摸内听牌，三向听看两摸内到一向听。

例如第一摸有两张同种牌可摸，每张摸到后还有四张第二摸能继续推进，这条分支贡献八个有序牌对。第一摸一旦被假设摸走，第二摸的同种剩余张数减一；即使随后把它打掉，也不能重新回到未知牌集合。

这里的未知牌是 `4 − visibleCounts[tile]`，包括对手暗手，并不是引擎实际牌墙。搜索只能取得公开观测；没有访问 `auditState()`、对手暗手或牌墙顺序。

## 两个候选策略

| 策略 | 允许改变哪些选择 |
| --- | --- |
| `ties` | 与 H0 相同向听数、相同有效进张数的平手出牌 |
| `same-shanten` | 所有与 H0 相同向听数的合法出牌，允许牺牲部分当前进张来换取两步发展 |

两种策略都保留 H0 的胡、碰、杠、亮倒，以及已经听牌时的动作。牌墙不足六张时也使用 H0。根节点只选择正式引擎提供的合法动作；假设中的中间出牌继续避开已亮倒对手的公开听口，全危险时按正式规则放行。

搜索只缓存同一次决策中的手牌向听数，候选之间共享这个缓存。没有跨对局保存手牌或隐含状态。相同搜索值先看当前进张，再保留 H0 的原选择，确保稳定复现。

## 如何判断有没有用

运行固定预算实验：

```sh
node ai/lookahead/study.mjs --out ai-runs/two-draw-new-run
```

输出目录必须是新目录。开始前写入 `plan.json`，固定源码哈希、两个候选、开发种子、新的独立测试种子、预算、选择与停止规则。

默认先给两个候选各运行 1,920 局开发评测：每个对手组合 16 个单局配对组、4 个连续 16 手配对组。按连续对局的净收益差筛选；两者开发均值都没有超过 H0 就停止。若选出候选，仅对该候选运行预定的 6,912 局新种子封闭评测：每个对手组合 32 个单局组、16 个连续组。不会根据区间追加牌局。

主指标是连续 16 手的净收益差，单位为底分/百手。两个对手组合为 `H0/H0` 和 `H0/greedy-speed-v1`，等权；组内覆盖六种座位排列。连续对局保留正式轮庄与积分。区间以完整配对组为重采样单位，开发结果与封闭结果分别报告。

每局保存完整审计牌谱，每步检查合法动作、84 张牌守恒和零和结算；每阶段抽样二次回放首组每个组合、座位、实验臂的第一手。报告分别列明总保存量和实际二次回放量。

## 解释结果时的边界

这只是公开牌效搜索。它没有模拟对手未来碰杠、出牌、胡牌和提前终局，也没有优化番数、杠分、亮倒和查叫收益。“两步概率”是一个结构指标，不能作为实际胡牌率或期望净分。

规则允许不代表应该：保留 H0 的碰杠亮倒取舍，可能限制收益。公开信息固定在当前时刻，也无法推断对手之后会打出什么牌。本轮实验先隔离检验更深牌效是否有实战价值；无论结果如何，都不自动替换游戏默认 H0。

实现见 `ai/lookahead/policy.mjs`，固定预算实验见 `ai/lookahead/study.mjs`。穷举、隐私、合法性、重放及停止规则测试见 `tests/ai-lookahead*.test.mjs`。

## 一个实际诊断局面

固定的额外 80 局 H0 轨迹中，两个策略分别改变了 43 次和 99 次出牌。相同向听版有 56 次减少了当前进张数。这批数据只用于解释行为，没有参与开发选择或封闭验收。

例如第 6 局第 11 步，自己已碰 9 筒，待出手牌为 `1筒 3筒 6筒 7筒 1条 2条 3条 5条 8条 白 白`，一位对手亮倒听 5、8 条。H0 打 7 筒，新策略打 1 筒；两者出牌后都是二向听。

| 选择 | 当前有效进张数 | 两摸内听牌的结构牌对数 | 结构比例 |
| --- | ---: | ---: | ---: |
| H0：打 7 筒 | 37 | 180 / 2550 | 7.06% |
| 新策略：打 1 筒 | 36 | 400 / 2550 | 15.69% |

这里未知牌共 51 张，有序不放回牌对为 `51 × 50 = 2550`。新策略愿意少一张当前进张，保留后续更容易衔接的组合；假设中的下一次出牌也不能随意打出对手的 5、8 条听口。这只是说明搜索为何改变选择，不能从这一局或表中比例推断实际得分更高。

公开观测及两个选择的完整分支保存在运行生成的 `ai-runs/two-draw-diagnostics-20261018/diagnostics.json`，第 6 局在 JSON 中采用从零开始的 `hand: 5`。诊断命令如下，输出目录同样必须是新目录：

```sh
node ai/lookahead/diagnose.mjs --out ai-runs/two-draw-diagnostics-new
```

完整实验完成后，可独立复核所有牌谱及统计：

```sh
node ai/lookahead/verify.mjs --out ai-runs/two-draw-new-run
```

## 在后续评测中复用

它是可直接构造的独立策略，不依赖训练权重。后续交叉对战可通过现有 runner 的工厂接口加载：

```js
import {runEvaluation} from './ai/runner.mjs';
import {lookaheadFactory} from './ai/lookahead/policy.mjs';

const id = 'two-draw-same-shanten-v1';
const report = await runEvaluation({
  candidate:id,
  incumbent:'H0',
  policyFactories:{[id]:lookaheadFactory({mode:'same-shanten'})},
  seed:'new-development-seed',
  split:'development',
  independentGroups:8,
  sessionGroups:2,
  sessionHands:16,
});
```

这个例子只返回开发报告；需要固定预算、保存牌谱与独立验收时，应使用前面的 `study.mjs`。复核旧结果时不要修改已写入计划哈希的 `policy.mjs` 和 `study.mjs`；新搜索或可学习特征使用新版本文件。
