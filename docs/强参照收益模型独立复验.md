# 收益模型对不亮倒 H0 的独立复验

上一轮混合教师训练的预定收益模型相对不亮倒 H0 为 +6.64 底分/百手，95% 配对组区间 [-5.43, 20.70]，尚未确认优势。模仿模型和收益模型之间的 +28.30 是次要事后比较，不能替代主要门槛。本轮只检验同一份冻结收益模型在新牌局里能否重现正收益。

## 发牌前固定

- 模型沿用上一轮 offline 检查点，所选第 8 轮，原始 JSON SHA-256 为 `e9374f999a3481c109a9605f3a59e1c18c5682cb6187ea38ece7105c917cac82`。不换成模仿模型，不更新权重。
- 规则、公开输入、完整合法动作、六种座位排列和真实连续轮庄均保持。
- 比较对象仍是不亮倒 H0。对手组合固定等权：不亮倒/H0、不亮倒/不亮倒、不亮倒/速度贪心。
- 各组合 16 个全新种子组，每组六种座位 × 两条轨迹 × 连续 16 手，共 **9,216 局实际评测**，候选轨迹 4,608 手、48 个完整配对组。
- 整组配对 bootstrap 5,000 次；主要净底分差的双侧 95% 区间全部高于零，才称本批支持相对强参照的优势。完整区间低于零则为负证据，跨零则为不确定。
- 子组和行为统计均为未经多重比较校正的描述。旧批次单独报告，不与本批相加来争取显著性。

上述预算在第一手发牌前保存，不因中途成绩追加、缩减或更换模型。本轮没有新增训练或验证；仅换发牌种子的复验不能证明换训练初始化、换数据后也能训练出同样好的模型。即使为正，也不自动替换游戏默认 H0。

## 复用已验证的考场

`ai/strong-confirm/` 只增加固定候选的计划、调度、来源检查、汇总与审计入口。实际对局和逐条牌谱重放沿用冻结的 `ai/strong-pool/evaluate.mjs`。旧模块的协议计划只替换评测种子和组数/进程数，外层复验计划检查它与原计划的这一精确对应，保留原训练配置用于来源说明，不执行任何采集或训练阶段。

原计划、模型清单、训练摘要、结果与完整审计的哈希一并保存。每个任务是一个完整种子组，最多四个本地进程。收齐后按固定组合和组号排序统计。每组精确核验候选模型哈希、种子、结算及完整牌谱，并重新计算整池/各子组区间。

```powershell
node --test tests/ai-strong-confirm.test.mjs
node ai/strong-confirm/study.mjs ai-runs/strong-confirm-20261020 ai-runs/strong-pool-20261020
node ai/strong-confirm/verify.mjs ai-runs/strong-confirm-20261020
```

小规模检查先跑真实混合采集、模型训练和旧审计，再启动固定检查点复验；核对来源/模型绑定、新种子、完整组汇总和逐条牌谱，要求被篡改的来源、计划或组分数被拒绝。已有目录拒绝覆盖。

比赛结束后可另做 `diagnose.mjs` 事后动作抽样：每组全部六种候选座位，手号固定为组号对连续手数取余。复放这些已有比赛，在相同公开局面比较模型实际动作与不亮倒 H0 的弃牌后向听、公开进张与动作种类。不读取真实牌墙进行评价，不新增比赛、不改模型，也不把局部牌效差异当成因果输分或必错动作。源码、模型、原牌谱与计划哈希单列保存，不参与主要检验。
