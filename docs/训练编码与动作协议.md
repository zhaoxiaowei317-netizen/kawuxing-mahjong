# 训练编码与动作协议

日期：2026-10-17。实现为 `ai/training/encoding.mjs`。本协议把当前环境的只读观测转为固定长度数值向量，把合法语义动作转为固定输出编号；本文不报告模型训练成绩或牌技提升。

## 1. 版本与接口

| 项目 | 固定值 |
| --- | --- |
| 规则版本 | `xiaogan-1.0` |
| 环境观测版本 | `kwx-observation-1` |
| 环境语义动作版本 | `kwx-actions-1` |
| 本训练编码版本 `ENCODING_VERSION` | `kwx-encoding-1` |
| 输入长度 `INPUT_SIZE` | 1085 |
| 输出长度 `ACTION_SIZE` | 88 |
| 牌河窗口 `RIVER_WINDOW` | 每家最近 6 张仍在牌河中的弃牌 |

导出的接口：

- `encodeObservation(obs)`：接收 `MahjongEnvironment.observation(seat)` 的只读对象，返回长度为 1085 的普通 JavaScript 数组，所有元素有限；不修改输入。
- `actionId(action)`：将环境语义动作映射为 0—87 的整数，拒绝未知牌种、动作类型、非法字段组合或多余字段。
- `legalActionIds(actions)`：返回去重、按编号递增排列的合法动作编号；没有合法动作时返回空数组。
- `decodeAction(id, legalActions)`：只返回当前合法列表中的原始动作对象；越界、非整数、未被遮罩允许或格式错误均抛错，不创造替代动作。
- `FEATURE_SCHEMA`：冻结的有序字段表，每项包含 `name`、`offset`、`size`、`normalization`，与本文偏移一致。
- `TILE_TYPES`：冻结的 21 牌种顺序。

模型文件应同时记录编码版本、输入/输出长度和牌种顺序。即使以后长度碰巧相同，只要字段含义或次序变化，也要更改编码版本并拒绝将旧权重静默当作兼容模型。

## 2. 牌种与相对座位

牌种向量统一按如下次序：

| 编号 | 引擎牌种 |
| --- | --- |
| 0—8 | `p1`—`p9`，一筒至九筒 |
| 9—17 | `s1`—`s9`，一条至九条 |
| 18 | `z5`，白板 |
| 19 | `z6`，发财 |
| 20 | `z7`，红中 |

未知牌不占真实牌种编号，不可打出，也不被编码成某张真实牌。牌种计数忽略手牌的排列位置；本人本次摸牌另有独立通道，因此打乱手牌数组不改变编码。

三家统一表示为相对座位 `r=0,1,2`：本人、下家、上家。绝对座位转换为 `(absoluteSeat - observerSeat + 3) % 3`。庄家、当前行动者、待响应牌来源、最后弃牌者、累计分和杠账本均采用该次序。编码根据观测中的 `player.seat` 查找玩家，不依赖 `players` 数组的序列化次序。

同时循环平移所有绝对座位及关联字段，编码结果保持完全相同。只交换两家不同的实际局面则会改变信息，不属于这种旋转不变性。

## 3. 1085 维输入完整布局

偏移从 0 开始。以下长度为 21 的牌种字段都使用上一节的牌种顺序。

### 3.1 本人和总可见牌：63 维

| 起始偏移 | 长度 | 字段 | 编码 |
| --- | --- | --- | --- |
| 0 | 21 | `own.handCounts` | 本人手牌张数 / 4 |
| 21 | 21 | `own.drawTile` | 本人当前摸牌独热；没有时全零 |
| 42 | 21 | `public.visibleCounts` | 环境允许看见的总计数 / 4 |

`visibleCounts` 来自环境白名单观测，不查询真实牌墙，不用全知信息扣减未知牌。

### 3.2 三家公开状态：每家 282 维，共 846 维

相对玩家 `r` 的起点为 `B = 63 + 282 × r`，对应 63、345、627。

| 起始偏移 | 长度 | `players.relative{r}` 下的字段 | 编码 |
| --- | --- | --- | --- |
| `B` | 21 | `revealedTileCounts` | 规则允许公开的手牌计数 / 4 |
| `B+21` | 21 | `riverCounts` | 完整当前牌河计数 / 4 |
| `B+42` | 21 | `melds.peng` | 该牌的碰组数 |
| `B+63` | 21 | `melds.ming` | 该牌的直杠组数 |
| `B+84` | 21 | `melds.an` | 该牌已完成暗杠的组数 |
| `B+105` | 21 | `melds.bu` | 该牌补杠组数 |
| `B+126` | 21 | `publicWaits` | 公开听口的牌种成员位，0 或 1 |
| `B+147` | 3 | `status` | 依次为亮倒位、手牌张数 / 14、未公开手牌张数 / 14 |
| `B+150` | 132 | `riverTail` | 最近 6 张当前牌河的顺序窗口，每格 22 维 |

本人也按“对其他人公开了哪些手牌”生成 `revealedTileCounts`：未亮倒时全零；亮倒时扣除本人保留的暗坎。本人完整手牌仍在偏移 0 的独立通道中。其他玩家只读环境提供的 `revealedTiles` 和 `hiddenTileCount`。

牌河窗口由旧到新、向右对齐。每格先放 21 维牌种独热，再放 1 维存在标记；不足 6 张时，左侧空格全部为零。窗口不包含已被碰杠取走的牌，完整河计数也以当前环境牌河为准。

本规则中，亮倒保留的暗坎身份隐藏；已经完成的暗杠牌面公开，因而可以出现在 `melds.an`。两种状态分别处理，不能因为名称里都有“暗”就统一展示或统一隐藏。

### 3.3 本人限制：105 维

| 起始偏移 | 长度 | 字段 | 编码 |
| --- | --- | --- | --- |
| 909 | 21 | `own.passedHu` | 本人过胡牌种成员位 |
| 930 | 21 | `own.passedPeng` | 本人过碰牌种成员位 |
| 951 | 21 | `own.buOpportunities` | 本次出牌回合的补杠机会成员位 |
| 972 | 21 | `own.reservedKongTiles` | 本人亮倒保留暗坎牌种成员位 |
| 993 | 21 | `own.supplementForbidden` | 本人副露中永久禁止补杠的牌种成员位 |

重复标记不累计。对手对应的私有字段不读入；即使在测试中将其额外塞进观测，也不能改变编码。

### 3.4 局面与分数：71 维

| 起始偏移 | 长度 | 字段 | 编码 |
| --- | --- | --- | --- |
| 1014 | 1 | `table.wallCount` | 剩余牌数 / 44 |
| 1015 | 1 | `table.gangChain` | 当前杠链次数 / 16 |
| 1016 | 1 | `table.base` | 底分 / 100 |
| 1017 | 1 | `table.round` | 当前局号 / 16 |
| 1018 | 3 | `table.totals` | 三家累计分，按相对座位并作有符号分数变换 |
| 1021 | 3 | `table.kongNet` | 本局已完成杠账本净分，按相对座位并作同样变换 |
| 1024 | 3 | `table.turn` | 当前行动者相对座位独热 |
| 1027 | 3 | `table.dealer` | 庄家相对座位独热 |
| 1030 | 3 | `table.phase` | 依次为 `discard`、`react`、`ended` 的独热 |
| 1033 | 21 | `table.pendingTile` | 待响应牌种独热；无响应时全零 |
| 1054 | 3 | `table.pendingSource` | 待响应来源相对座位独热；不存在时全零 |
| 1057 | 2 | `table.pendingKind` | 依次为 `discard`、`robKong`；不存在时全零 |
| 1059 | 1 | `table.pendingGangShot` | 杠后炮链次数 / 16；不存在时零 |
| 1060 | 1 | `table.pendingGangCount` | 待抢补杠链次数 / 16；不存在时零 |
| 1061 | 21 | `table.lastDiscardTile` | 最近弃牌牌种独热；不存在时全零 |
| 1082 | 3 | `table.lastDiscardSeat` | 最近弃牌者相对座位独热；不存在时全零 |

分数变换为 `asinh(score / base) / asinh(100)`，保留正负号并压缩大分数；它仅用于网络输入，实际奖励和报告仍用真实净分。三家转换后的数值不要求相加为零。

`totals` 是环境的累计分，局中尚未结算的已完成杠另由公开账本算出 `kongNet`。这两个输入通道不代表额外支付奖励；终局奖励不可因此重复加杠分。

这些归一化是固定比例和变换，不做截断。例如局号超过 16 后，`round / 16` 可以超过 1。`cap=16` 属于规则常量，编码入口验证它，不再占一维。

## 4. 88 个固定语义动作

设牌种编号为 `t=0…20`：

| 动作编号 | 环境对象 | 意义 |
| --- | --- | --- |
| `t`，0—20 | `{type:'discard', tile, reveal:false}` | 打牌，不亮倒 |
| `21+t`，21—41 | `{type:'discard', tile, reveal:true}` | 打牌并亮倒 |
| `42+t`，42—62 | `{type:'kong', tile, kind:'an'}` | 暗杠 |
| `63+t`，63—83 | `{type:'kong', tile, kind:'bu'}` | 补杠 |
| 84 | `{type:'hu'}` | 当前阶段合法的自摸、点胡或抢杠 |
| 85 | `{type:'peng'}` | 碰当前待响应牌 |
| 86 | `{type:'ming'}` | 直杠当前待响应牌 |
| 87 | `{type:'pass'}` | 过当前响应 |

同牌多张只产生一个语义打牌动作。实际打哪张实体牌以及亮倒后的强制摸切索引，由现有环境适配器处理，不让网络预测手牌索引。

动作输出只在 `legalActionIds(env.legalActions())` 允许的位置选择。自摸可以不胡，通过其他合法打牌或杠表达选择；不增加本回合无意义的空过动作。反应阶段的过牌由环境合法列表提供。终局或没有决策时，不应对空遮罩作概率采样。

编码器不重写麻将合法性。亮倒避炮、全手危险例外、保听杠、屁胡起胡条件、抢杠与过手限制，均由环境/引擎生成合法动作并在 `env.step()` 再验证。`decodeAction` 无权凭编号绕过此边界。

## 5. 明确的信息边界与本版限制

编码只接受带正确版本的环境观测；直接传入真实 `g` 会被拒绝。它不查询真实牌墙、不调用审计状态、不读取对手暗手、暗坎身份、过手限制、弃牌手牌索引或未公开响应。

输入不解析 `publicActionLog` 的中文文本，也不编码绝对姓名、房间令牌、随机种子、结果 ID、杠账本的说明文字或数组中的未知牌位置。可见计数及合法动作的保密性仍依赖环境的白名单；编码器并不是允许上游混入全知字段的理由。

这是紧凑的第一版特征，不声称无损保存全部公开历史：牌河只保留每家最近 6 张的局部顺序、完整计数及最近一次全局弃牌；更早的逐次顺序、已经取走的河牌、三家行动的完整交错次序没有序列化。未来若加入结构化完整事件或记忆网络，应发布新编码版本并作对照，而不是在同一版本下改变输入含义。

输入检查覆盖版本、固定牌种、玩家座位、主要结构与有限数值；它不替代环境的牌守恒和完整规则检查。全部有限的合法极端分数也会生成有限特征；非有限输入或不兼容协议会抛错。

## 6. 验证方式

运行 `node --test tests/ai-encoding.test.mjs`。测试覆盖：

- 全部 88 个动作的编号与往返映射，合法集合去重及严格拒绝非法输出。
- 固定 schema 连续、长度正确、字段不可变；真实只读环境观测在完整对局中生成有限向量，并通过合法解码执行动作。
- 所有绝对座位循环平移后，相对特征一致，包括杠账本、抢杠来源和累计分。
- 改变对手隐藏暗坎身份、隐藏排列、未知墙牌或额外私有诱饵字段，编码不变。
- 本人各过手与补杠限制的独立成员通道、牌河顺序与空格存在标记、有限数值边界及协议不兼容拒绝。

这些检查验证表示与接口边界，不证明网络会学出更强打法。牌技仍需在独立对战考场中比较真实净得分。
