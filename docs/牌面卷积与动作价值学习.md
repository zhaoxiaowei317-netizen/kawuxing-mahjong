# 卡五星牌面卷积与动作价值学习

本路线将公开强麻将 AI 的部分方法系统地适配到 `xiaogan-1.0`：逐张牌的卷积表示、合法动作价值学习、离线训练，再使用当前模型继续生成经验。所有训练和评测使用本地正式规则引擎，默认游戏电脑仍为 H0。

## 方法依据与适配边界

Mortal 的公开实现使用残差卷积编码器与合法动作遮罩下的 dueling Q 输出。训练代码用实际动作的蒙特卡洛回报做回归，离线阶段加入 CQL 正则，并辅以顺位预测。[模型源码](https://github.com/Equim-chan/Mortal/blob/main/mortal/model.py)、[训练源码](https://github.com/Equim-chan/Mortal/blob/main/mortal/train.py)。本项目独立实现这些机制，未复制 Mortal 源码、导入其日麻模型或权重，也不声称复现其公开成绩。

本版本作了以下适配：

- 21 种牌、固定三人、84 张牌与卡五星计分；保留现有正式规则和合法动作实现。
- 两种数牌分别作为连续的九张序列；三种字牌分别隔离。每次卷积后清零间隔位置，避免把筒九与条一、不同字牌当作相邻数牌。
- 小型残差网络用 ReLU，不包含 Mortal 的归一化、注意力及大规模编码器。
- 采用共享的动作条件价值输出，同时输入已有的 34 个公开牌效特征；这是一项本地适配，不是纯原始牌面模型。
- 优化目标为底分净收益；辅助任务预测当手结算后的累计顺位分布，平分顺位按并列位置分摊。没有移植日麻段位奖励或全局顺位奖励预测器。
- 直接拟合完整蒙特卡洛回报，没有引入 TD 自举或宣称使用 Double DQN。训练并不使用 PPO。

Meowjong 对三人麻将的二维牌面表示、分动作学习也有参考价值，但本版本没有复现其五个独立 CNN。[Meowjong 论文](https://arxiv.org/abs/2202.12847)。Suphx 的全局奖励预测、oracle guiding 和在线参数适应尚未实现。[Suphx 论文](https://arxiv.org/abs/2003.13590)。

## 观测与全部动作

模型接收 65 个牌面通道、42 个全局字段，以及每个合法动作的 34 个牌效特征。牌面包括本人逐张手牌及顺序、摸牌、公开可见数量、三家的公开副露、亮倒听口、全部牌河与顺序，以及本人的过手和补杠限制。

每种牌至多出现四次，牌河顺序用该牌第 1～4 次出现的位置编码，保留整条牌河，而非只截取最后几张。它没有编码全部玩家事件交错顺序，亦没有额外推断对手暗牌分布。对手手牌、真实牌墙、环境种子和最终奖励都不会成为模型输入。

动作使用原有 88 个语义编号，覆盖普通出牌、出牌并亮倒、暗杠、补杠、胡、碰、明杠和过。网络给全部合法动作估值，每个需要选择的决策点都由模型作决定；只有一个合法动作时直接执行该动作。没有每手一次的提案限额，也没有固定回退 H0 的策略入口。

Q 输出为状态价值与动作优势之和，并减去当前合法动作优势的平均值；非法动作在训练中设为负无穷，推理只在引擎给定的合法动作中取最大值。CNN 使用相同卷积处理筒条，结合共享动作输出，可检验交换两种花色后的行为一致性。

## 数据与训练阶段

初始数据由固定混合行为生成：每个需要选择的动作，85% 使用 H0、10% 使用 greedy-speed、5% 均匀选择合法动作。每个选择点另记 H0 教师动作，终局后为实际执行动作填写回报。没有选择余地的动作保留在牌谱中，不重复制造策略训练样本。

正式采集使用 16 手连续环境，保留实际轮庄和累计分，分片必须在连续对局的边界开始，避免训练只见过第一局、零累计分的状态。主要回报仍衡量当前这一手之后的净分，并未估计未来各手改变轮庄带来的全部收益；辅助预测的是当前手结算后的累计顺位。

回报为“本人本手最终净得分 − 在该决策点之前已经记入杠账的净分”，再除以 16。它衡量此后尚能影响的得失，包含之后发生的胡分、杠分和查叫，既不裁剪奖励，也不把过去杠费重复当作未来收益。训练时的暗牌仅存在于规则引擎和审计牌谱中，训练器只读取公开编码、合法动作、动作标签、回报和辅助顺位标签。

四个正式候选使用同一批初始训练与验证数据：

1. **features-bc**：关闭原始牌面卷积分支，仅使用全局字段及动作牌效，做教师模仿。
2. **tiles-bc**：开启卷积牌面分支，其余网络尺寸、初始随机种子、训练数据和优化预算相同，做教师模仿。
3. **tiles-offline**：从 tiles-bc 的固定所选快照出发，用实际动作回报回归、CQL、少量教师约束和辅助顺位任务训练。
4. **tiles-online**：从离线快照出发，分轮重新对战采样和更新。对手包括 H0、greedy-speed、冻结的历史模型以及当前模型自博弈；只有当前学习者自己的选择进入新训练集。

“关闭牌面分支”的模型仍计算公开牌效，其训练中不使用卷积特征，不能把它叫作纯随机或最基础贪心。该对照帮助检查额外的逐牌表示是否值得，BC→offline→online 的阶段对照帮助检查价值学习是否带来额外收益。

模仿阶段以验证交叉熵加辅助损失最低的轮次为准；离线阶段以预定验证组合损失最低的轮次为准，均包含第 0 轮，误差相同取较早轮次。在线各轮使用固定最后一轮，不拿旧行为验证集的误差挑选在线候选。正式牌技仍由单独的开发和封闭评测判断。

离线 Q 目标包括 `0.5 × MC均方误差 + 0.05 × CQL + 0.1 × 教师交叉熵 + 0.1 × 顺位损失`。在线关闭 CQL，教师权重为 0.02，其余权重保持。它是有限资源下可消融的本地配方，不预先认定最优。

## 运行与复核

使用项目 Node.js 和已有的 Python/PyTorch 环境。当前本机环境为 Python 3.11、PyTorch 2.1.2 CPU、NumPy 1.26.4，未安装新的训练依赖。精确续训测试基于相同运行时和线程设置；更换版本或硬件后应重新检查数值一致性。

```powershell
node ai/tile-q/study.mjs ai-runs/tile-q-001
node ai/tile-q/verify.mjs ai-runs/tile-q-001
python tests/test_tile_q.py
node --test tests/ai-tile-q.test.mjs
```

大规模审计也可选用 `node ai/tile-q/verify-parallel.mjs ai-runs/tile-q-001`，分配四个本地 CPU 进程调用同一套冻结的逐局复核函数。它另行核对全局计划、数据种子、模型选择和各阶段预算，并记录审计驱动源码哈希。与串行审计使用同一输出名，均拒绝覆盖，选择一种运行即可。

计划在第一手数据之前写入，保存阶段种子、源码哈希、网络、配方和预算。四个候选分别完成固定开发评测；仅在最高连续对局净分差为正时，固定该候选并用新种子对 H0 做封闭验收。没有候选通过开发门槛时，不启动封闭评测。分差按完整配对种子组重采样，对手组合等权；开发结果不冒充独立强度证据。

每个训练快照同时保存 PyTorch 参数与 Adam 状态，以及 JavaScript 推理权重。训练器区分“只复制权重开展新阶段”和“连优化器一起精确续训”；续训严格核对数据哈希、源码、种子、配置及绝对轮次。每轮打乱顺序由该轮独立种子决定，便于精确恢复。

复核从种子重新发牌，逐步检查训练行为、公开编码、教师标签、动作掩码、杠账、终局奖励和顺位标签。训练与推理之间另有同一公开输入下的数值一致性检查。实际评测保存完整牌谱，并核对发牌、轮庄、双方策略动作、收益汇总和统计结果。

本轮没有使用目标规则的真人高手牌谱，初始教师仍为 H0；训练和模型规模也远小于成熟系统。因此本路线交付的是可运行、可验证的适配版本，强度以独立对局收益为准。
