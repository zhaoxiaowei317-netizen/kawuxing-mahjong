# 动作牌效模型与同数据对照

此前原始牌面网络在自身局面中约有 14% 的自由出牌没有选取最低向听。碰与过的模仿也不稳定。本轮把每个合法动作对应的牌效显式交给模型，检查同样数量的老师牌局是否能训练出更好的策略。

本轮已完成，见[实训结果](reports/action-scorer-2026-10-18/实验结果.md)：相对同数据旧网络和上一轮纠错模型均获得独立评测支持的提升，尚未证实超越 H0。

## 模型与信息边界

`ai/action-scorer/` 使用共享线性评分器：对每个合法动作计算 34 个特征，动作分数是这些特征与同一组权重的内积，随后在合法动作之间做 softmax。另有 10 个上下文特征供线性价值头使用。BC 只训练动作头；实现也包含经数值梯度验证的 PPO 损失，但本轮实训不使用 PPO。

特征包含动作类型、动作后向听、向听变化、公开信息下尚未出现的进张数、听口、潜在番数、亮倒条件、持牌数量及手牌顺序。亮倒的若干阈值借鉴现有 H0。模型推理不会调用 H0、读取老师答案或访问其他玩家暗手及牌墙顺序。

进张数包含对手暗手中的未知牌，不能解释为牌墙内确实还剩多少张。潜在番数来自假设胡牌的牌型分析，并非保证得到的结算分数。碰后的牌效取结构上最好的一次后续出牌；尚未套用下一回合的危险牌限制，实际下一步仍只能在规则引擎给出的合法动作中选择。杠的牌效在未知补牌摸取之前计算。

线性模型容量有限，也尚未显式建模对手听牌概率、未来收益分布及各家相克关系。这一轮首先验证牌效表达能否补上基础选择能力。

## 预先固定的对照

三个训练种子，每个采集 600 局 H0 对局。每个动作同时保存原始编码和动作牌效编码，两个模型看到完全相同的局面、合法动作和 H0 标签。两者各训练 12 遍，同一轮的打乱种子相同，批大小 128。

对照是原有 64 隐层网络，学习率 0.001；动作评分器学习率 0.02。两者都使用 Adam 和 0.5 全局梯度范数上限。由于手工特征、容量与学习率不同，这是**同数据下两套表示及训练配置的比较**，不是单一架构消融，也不是计算量相等的对照。

另外 120 局固定 H0 验证数据不参与训练。第 4、8、12 遍保存模型，每个种子和模型类型各自按验证交叉熵选择一次。报告排除唯一合法动作后的选择一致率和各动作分项；一致率不等同于实战牌技。

开发评测包含两个对手组合：H0+H0、H0+速度策略。每组合 8 个独立单局组和 1 个完整 16 局组，每组包含六种座位排列及候选、对照两臂。每类模型各选开发完整 16 局净分最高的种子。

两个候选都固定后，动作评分器分别对比 H0 和原始网络，使用新封存随机种子，每对手组合 32 个独立单局组和 8 个完整 16 局组。封存种子的 SHA-256 在训练前保存，牌局在选模后生成。两项完整 16 局配对分差的 95% 区间下界均大于零，才支持本次候选在这些对手上的提升。区间以整组为重采样单位；组内座位和各手不能当成独立样本。开发结果仅用于选模，不能用于证明提升。

## 运行

```powershell
node ai/action-scorer/experiment.mjs --out ai-runs/action-scorer-new
```

可用 `--config 配置.json` 覆盖 `DEFAULT_CONFIG` 中的字段；输出必须是新目录。默认新增 1,800 局训练数据（两种编码共用），120 局验证数据，11,136 局评测。模型和日志写入 `ai-runs/`，不更换游戏电脑，不接触房间数据或浏览器存档。

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 训练前固定的设计、源代码版本、封存种子承诺 |
| `status.json` / `events.jsonl` | 当前状态及完整进度 |
| `seed-N/data.json` | 该种子局数、动作数及老师动作分布 |
| `seed-N/raw-history.json` / `structured-history.json` | 验证学习曲线及保存模型 |
| `development.json` | 六个候选的开发结果 |
| `selection-frozen.json` | 封存评测开始前选定的两个模型 |
| `sealed-vs-H0.json` / `sealed-vs-raw.json` | 原始分组记录与配对统计 |
| `*-replays.jsonl` | 按两臂、对手、测试集与座位抽取且已重放的审计样本 |
| `summary.json` | 完成情况、计数、模型与统计结论 |

新模型使用独立的 `saveScorer` / `loadScorer` 格式，包含完整 Adam 状态和特征源码哈希；恢复后可精确延续模型更新。它不兼容原始网络的 `ai:train --resume`，也没有自动恢复整个未完成对照实验的入口。中断的已有输出应保留，重跑整套实验使用新目录。旧模型及其续训代码未改动，旧检查点仍可按原流程使用。

每局持续检查合法性、牌数守恒与零和结算；每份评测实际重放 48 个分层审计样本。封存数据报告后即视为已使用，后续修改模型需要新验收批次。

## 单独评测保存的动作模型

```powershell
node ai/action-scorer/evaluate.mjs --model ai-runs/你的实验/seed-0/structured-epoch-12.json --out ai-runs/新的评测
```

默认与 H0 比较，使用新随机封存种子。添加 `--incumbent 原始模型.json` 可以对比旧网络；若对手也是动作评分器，再添加 `--incumbent-kind structured`。可显式指定 `--seed`、`--split development`、`--groups` 和 `--session-groups`。不得把已用于选模的种子标成独立封存集。

单独评测入口记录候选、对照的完整哈希、协议与源码；每局完整审计牌谱压缩追加到 `replays.jsonl.gz`，48 局分层样本现场重放，完整回放可另外验证。压缩文件由多个 gzip 成员串接，Node 的 `gunzipSync` 可一次解压。

本轮还在主实验封存评测开始前固定了一个补充计划：用另一批牌局比较主实验选中的结构化模型与上一轮最好的 teacher-refine 第 3 轮模型。该补充不参与选模，用于检验相对此前成果的进展。
