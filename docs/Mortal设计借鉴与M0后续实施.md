# Mortal 设计借鉴与 M0 后续实施

日期：2026-10-17。目标规则为 `xiaogan-1.0`，三人固定、21 种牌、84 张。本文件将公开项目的方法转为本项目的接口与实验设计；下述神经编码、训练与并行架构是后续提案，不能当作已经实现或已经训练的功能。

本文件为 M0 阶段的设计记录。M0 考场与基准现已完成，21 牌种、88 动作和小网络训练机制也已落地，实跑见[训练机制指南](AI训练机制与运行指南.md)。尚未引入外部权重；本文件其余扩展架构仍是提案。里程碑和晋级标准以[AI 牌技提升与评测方案](AI牌技提升与评测方案.md)为准，公开项目适用范围见[调研记录](公开麻将AI借鉴与卡五星适配.md)。

## 1. 借鉴对象与边界

Mortal 将麻将模拟与神经推理、训练分开组织；公开模型包含输入编码器、动作价值头及合法动作遮罩。其价值头会屏蔽非法动作。这些接口思想可借鉴，模型原来的输入输出含义不能直接搬进卡五星。[Mortal 项目](https://github.com/Equim-chan/Mortal)、[模型源码](https://github.com/Equim-chan/Mortal/blob/main/mortal/model.py)

Mortal 当前公开训练程序使用动作价值学习，离线阶段包含 CQL 正则与辅助预测；它不是 PPO。我们可以分别实现小型 PPO 基线与价值学习对照，但不能把 PPO 称作复现 Mortal，也不能因一种方法在日麻有效就认定它在卡五星更强。[训练源码](https://github.com/Equim-chan/Mortal/blob/main/mortal/train.py)

mortal-sanma 的参考价值是检查四人改三人时哪些座位、结算和编码假设需要同时改变。它仍是三人日麻，包含本项目没有的拔北、日麻役种等机制；其输入维度和动作表不是卡五星的模板。[三人分支说明](https://github.com/Mateces/mortal-sanma)

具体采用的工程方式由我们自己实现，继续以本地 JavaScript 引擎为唯一规则依据。若以后引入外部代码，再锁定提交并核对代码、数据、权重各自的许可与来源；本次仅做设计参考，未复制外部实现。

## 2. 先固定环境边界

策略只需要 `choose(observation, legalActions, policyRandom)`，不能收到引擎完整状态 `g`。环境负责发牌、生成合法动作、应用动作、结算与审计。`src/engine.js` 的下列接口承担现有规则职责：

| 现有接口 | 环境适配职责 |
| --- | --- |
| `newGame` 与可注入随机函数 | 构造可复现的起手；环境随机与策略随机分流 |
| `canWin`、`reactionOptions` | 生成本人自摸、点胡、抢杠、碰、直杠和过的候选 |
| `discardPolicy`、`waits` | 枚举符合避炮、锁手和听牌条件的弃牌与亮倒弃牌 |
| `selfKongOptions` | 枚举本人的暗杠、补杠，不复制过手及亮倒保听规则 |
| `discard`、`respond`、`kong`、`finish` | 执行动作并再次校验合法性 |
| `revealedWaits`、`visibleCounts` | 提取规则允许的听口与可见牌，核对编码计数 |
| `winSettlement`、`drawSettlement` | 提供实际净得分与解释，作为奖励和报告的依据 |

反应阶段的两家应各自基于当时可见信息决策。第二家不能因为评测器先调用了第一家，就看到第一家尚未公布的“胡、碰、杠、过”选择。请求顺序和内部收集状态也不能成为暗示。

只有环境可持有真实牌墙、对手暗手和随机种子。相同初始牌局的六种座位排列、配对比较与重放均在环境层完成，不能通过给策略种子或真实牌墙来实现可复现。

## 3. 卡五星自己的观测结构

### 3.1 牌种与座位

以引擎 `TYPES` 的次序固定 `tile-v1`，记录在模型清单中：

| ID | 牌种 |
| --- | --- |
| 0—8 | `p1`—`p9`，一筒至九筒 |
| 9—17 | `s1`—`s9`，一条至九条 |
| 18、19、20 | `z5` 白板、`z6` 发财、`z7` 红中 |

每种最多四张。未知牌使用独立遮罩或未知标记，不能当成第 22 种可打牌，也不能编码成某个真实牌种。不得默认 `z5` 是红中。

模型统一采用相对座位：本人、下家、上家。庄家、出牌者、放杠者、付款者等全部随之转换；实际账号名和房间令牌不进入模型。调度器在动作执行和计分时再映射回绝对座位。

### 3.2 第一版输入提案

先保留结构化观测，后由版本化编码器生成牌种特征、数值特征和事件序列，避免过早把大量字段固化成不可解释的大张量。

| 部分 | 应包含的内容 |
| --- | --- |
| 本人私有信息 | 本人手牌计数、本人摸到的牌、本人副露、本人的过胡/过碰限制、补杠机会及禁止补杠标记、本人亮倒后保留的暗坎与固定听口 |
| 三家公开状态 | 副露及杠类型、弃牌与顺序、亮倒状态、公开听口、规则允许看见的亮倒手牌、未公开部分的遮罩 |
| 牌种特征 | 本人计数、各家可见弃牌与副露计数、已知亮倒手牌、总可见计数、本人合法弃牌/亮倒/杠遮罩 |
| 局面数值 | 剩余牌数、相对庄家和当前行动者、阶段、待响应牌及来源、当前杠链、底分、累计分、当前局号与对局长度 |
| 公共事件序列 | 摸牌发生但不含未知牌面、弃牌、亮倒、碰、明/暗/补杠、抢杠阶段与公开结算；保留相对行为者、牌种及必要事件属性 |

计数先保持整数，网络输入时再作固定尺度处理。公共事件使用明确长度与 padding 遮罩；若截断长历史，应把当前副露、牌河、公开计数与本人过手状态保留在状态特征中，不能仅剩截断后的事件。

起步可以比较“紧凑静态特征”和“静态特征加小型记忆网络”。21 种牌的排列并不表示九条与白板相邻成顺子；可用牌种、花色和点数嵌入表达结构，卷积方案则要避免跨花色边界误建连续关系。选择依据是相同计算预算下的收益与推理耗时。

### 3.3 亮倒与暗坎的信息边界

本规则中，亮倒时可保留且开杠不改听的暗坎盖住，身份不能提供给对手；已完成暗杠的具体牌面按已确认规则公开。两者不能混为一谈。[正式规则：亮倒与信息](孝感卡五星正式规则.md)

对手观测中不出现：

- 未亮倒暗手、亮倒保留暗坎的牌种及 `liangKongTiles`、内部带牌值的 `liangWaits`；公开听口只提供规则允许的牌种。
- 对手 `dealHand`、`passedHu`、`passedPeng`、`buOpportunities`、`supplementForbidden` 等内部标记。
- 真实牌墙、未来补牌、未知摸牌牌面、审计种子、完整游戏对象或引用。
- 尚未公布的其他响应选择、弃牌原手牌索引 `lastDiscard.handIndex`、服务器令牌及调度器内部信息。

未知牌种不能从其他衍生字段泄漏，例如全知向听、对手真实听口评分、预留暗坎名称、隐藏牌对应的数组排序或日志。可见牌总数只能由允许公开的数据计算，不能把完整牌堆减掉后称为“推断”。

保密验收采用成对状态：改变暗手或未知墙牌，保持该玩家自己的私有信息和全部公开历史一致，检查观测、合法动作以及固定策略随机流下的输出一致。公开信息确实变化的情况另测，不要求策略忽略新公开的杠或亮倒听口。

## 4. 固定语义动作与合法遮罩

M0 可以用可读对象动作。后续神经模型建议采用独立版本 `kwx-action-v1`，共 88 个输出；这是一份编码提案，不代表 M0 已使用同样的数字 ID。

设牌种 ID 为 `t ∈ [0,20]`：

| 输出 ID | 语义 |
| --- | --- |
| `t`，0—20 | 打出该牌，不亮倒 |
| `21+t`，21—41 | 打出该牌并亮倒 |
| `42+t`，42—62 | 以该牌暗杠 |
| `63+t`，63—83 | 以该牌补杠 |
| 84 | 胡：由当前阶段解析为自摸、点胡或抢杠 |
| 85 | 碰当前待响应牌 |
| 86 | 直杠当前待响应牌 |
| 87 | 过当前响应 |

不设置吃、立直、拔北、加漂、买马或第四家动作。碰、直杠的对象已经是唯一待响应牌，不需要再扩展 21 个同义输出。弃牌和亮倒弃牌必须分开，不能把亮倒永久藏在自动规则中。

同牌多张只产生一个语义弃牌动作，由适配器映射到合法手牌索引。亮倒强制摸切时，须映射到本次摸牌对应的合法索引；不能让网络学习“点第几张牌”这种排列偶然性。M0 的 H0 兼容适配应额外核对同分候选顺序，避免所谓冻结基线因换了映射而悄悄变招。

遮罩由引擎当前合法动作生成，策略仅在有效位置取样或求最大值；执行前再次核验。自摸可以放弃，但不提供无意义的本回合“空过”动作：通过其他合法弃牌或杠动作表达选择，过胡限制仍由引擎记录。反应阶段保留合法的过牌选项。没有决策可做时由环境推进，不要求模型在全零遮罩上运行。

非法输出应使训练样本或参赛版本显式报错并留下重放定位；不能悄悄替换成最好动作而让报告继续宣称合法。模型输出、编码器与动作表版本不匹配时也应拒绝运行。

## 5. 本地规则如何进入决策和奖励

| 特有规则 | 输入与执行要求 | 学习与诊断重点 |
| --- | --- | --- |
| 屁胡可自摸，普通未亮倒点胡不合法 | 胡牌遮罩区分自摸与点胡；亮倒方的倍数由引擎判断 | 胡牌机会与收益不能按日麻役种迁移 |
| 亮倒与强制避炮 | 独立亮倒弃牌动作；公开听口、剩余牌数、锁手与全手危险例外入环境 | 比较立即翻倍收益、锁手成本、查叫风险；死听可亮倒不等于值得亮倒 |
| 四归、七对、全求人等牌型 | 最后胡到的牌、本人手牌与副露明确；牌型与向听继续调用现有接口 | 四张算两对；第四张必须为最后胡牌张，不能用普通日麻标签替代 |
| 连杠与杠后胡牌 | 当前链数、杠后弃牌、抢补杠阶段作为公开状态；直杠延链与普通摸牌中断交给引擎 | 比较即时杠分、补牌、抢杠风险和后续倍数；杠分不是固定一次性常量 |
| 过胡、过碰、补杠窗口 | 仅本人限制进入观测；合法动作由引擎生成 | 避免模型把已经失去的补杠机会算成未来可选项 |
| 海底与查叫 | 剩余牌数、亮倒状态与本人结构性听牌信息可见 | 流局奖励按最高听口和亮倒条件结算，不额外虚构杠开、海底等事件 |
| 每笔胡分/查叫 16 倍封顶 | 奖励使用最终实际转账；杠分独立计算 | 原始倍数可作解释，不能用无限倍数替代实际收益 |

第一版训练奖励可采用局末本人 `result.delta[seat] / base`，该值已经包含本局完成的杠与最终胡牌或查叫。此时中途奖励为零，不能又把每次杠收入追加一遍。每局终止时，三家各自尚待完成的轨迹都要收到结算，不能只奖励最后行动的人。

若后来使用即时杠分奖励，则建立转账账本并使最终奖励只含尚未计入的部分，验收整局奖励和严格等于净得分。收益目标为完整净分时，先采用不因动作数量打折的回报定义；训练算法若引入折扣或奖励整形，须记录它如何改变目标并作消融。向听、活张、胡牌和听牌预测只作辅助任务，不能替代主目标。

16 局评测真实运行后续庄家和累计分。第一版可先做每局净分学习，同时观察完整对局表现；若改为优化整桌顺位，要另列目标与报告，不能沿用“净得分提升”的解释。

## 6. 重放、训练样本和 actor/learner 分离

### 6.1 两类记录分别保存

**审计重放**保存规则、引擎与策略哈希、所有随机源、初始完整状态、全部已执行动作和结算，用于精确排错。它包含隐藏信息，不直接进入策略或特征编码器。重放比较语义状态、动作与结算；运行时间、随机生成的结果 ID 和时间戳不应成为复现成败的依据。

**策略经验**只保存该玩家行动时的观测、当时合法动作遮罩、已选语义动作、策略版本、所需的行为概率或价值、奖励、终止标志与轨迹位置。奖励与未来结果可作为学习标签，未来牌面不能回填为当时输入。每个玩家的记忆状态单独管理，对手的私有经历不能混入共享记忆。

每个样本附有 `rulesVersion`、`observationVersion`、`actionVersion`、策略版本和来源层级。训练只读训练层；开发和封存评测牌谱另存，不能因为它们也能重放就混入训练缓存。

### 6.2 最小可行的数据管线

1. Actor 运行本地规则环境，用冻结的策略快照生成牌谱或轨迹；同桌三个策略分别接收自己的观测。
2. 批量推理服务仅接收观测与遮罩。先实测单进程与少量工作进程，再决定批大小，不能根据逻辑核心数直接开满。
3. Learner 读取训练轨迹、更新参数、保存带哈希的 checkpoint；actor 只在声明的边界切换版本，轨迹中记录实际行为版本。
4. 评测器读取冻结候选和固定对手池，使用独立种子及配对赛程，产出报告；不参与更新参数。

PPO 使用对应行为策略的近期轨迹，并保留训练所需概率；不得把任意陈旧经验混用后仍称标准 PPO。若做离线价值学习或经验回放，则单独定义回报目标、数据混合和分布外动作约束。两条算法路线共享规则、信息边界、编码和考场，不共用未经检查的采样假设。

开始时用进程内结构化接口，必要时再加批量 JSON/进程通信。只有吞吐分析证明规则模拟是瓶颈，才评估更换运行时；若重写 Rust 等环境，必须与现有引擎逐动作对照，不能只核对一局最终得分。

## 7. 从 M0 到首个学习模型的顺序

| 阶段 | 要做的事 | 允许作出的结论 |
| --- | --- | --- |
| M0 | 冻结 H0，完成公平观测、合法动作、重放、配对单局与完整对局报告；建立同策略对照应为零的检查 | 考场可运行、可复现；H0 在所列对手和预算下的表现，不宣称已经提升 |
| H1 开发 | 每次改变少量决策假设，如亮倒时机、碰杠取舍、活张和风险估计；保留 H0 | 按开发成绩筛选；封存评测满足预定标准后，才称 H1 在对应范围有提升 |
| 小网络闭环 | 用本地合法轨迹作模仿起点，验证语义动作、序列记忆、遮罩与终局奖励；报告参数量、吞吐和耗时 | 训练链路有效；模仿准确率不代表超过老师 |
| 算法对照 | 先让一种小型 PPO 实验跑通，再在相同资源约束下比较价值学习等路线；记录多个训练随机种子 | 用独立对战收益判断方法价值，不能以训练损失降低或自博弈平均零分证明更强 |
| 联盟与搜索 | 对历史强者和不同对手组合训练；再加入公开信息推断与预算受限搜索 | 保留有明确优势的通用冠军或专家，分别标注计算预算与适用条件 |

H1 不需要等神经模型。它既提供能解释的改进假设，也能生成质量更高的本地经验；若某次手写“改进”实际退步，保留失败报告，避免把偏好写成训练标准答案。

各阶段遵守同一评测原则：同初始牌局六种座位排列、新旧配对、按初始牌局整组估计区间、固定两对手组合与权重、完整 16 局验证、记录推理预算。随机合法策略仅作检查；战胜随机、单次大胜、训练曲线上升都不能单独支持升级结论。

近期优先级是把 M0 的实际基准变为下一轮决策依据，再确定一个可检验的 H1 假设。训练架构、模型规模与大批量局数根据实测吞吐和配对方差决定，不承诺未经测量的工期或高手等级。
