## 1. 目标与“多个强 AI”

默认目标：在合法信息与明确计算预算下，尽量提高面对多种对手时的长期期望净得分。胡牌、杠分、流局查叫都计入收益，不单独追求胡得多或做得大。

运气造成短期成绩波动；策略差异、训练路径与对手组合，也可能使多个模型各有优势。允许出现 A 擅长对付 B、B 擅长对付 C、C 又能压制 A 的循环。三人场还会受到第三家的打法影响，不能把单个对手上的胜负当作绝对排序。

因此维护三类成果：

- **通用冠军**：在预先固定的对手组合分布上，长期净得分证据最好。
- **有价值的专家**：在特定对手组合、牌局状态或风险要求下，优势明确且可重复。
- **组合策略**：根据实战可观察信息选择或混合多个模型，作为独立的新参赛者重新评测。

专家的价值须以实测证明。仅仅换一个随机种子、起一个“进攻型”名字，或在少数牌局赢得多，都不构成保留理由。低风险目标与最大期望得分是不同目标，分别标注，避免混成一个“智能分”。

## 2. 先建设独立考场

冻结当前电脑为 `H0`，连同规则源码版本、策略文件哈希、参数、随机策略一同保存。后续不能一边修改 H0，一边声称打败了同一个基线。

评测器先于学习器建设，最低提供：

| 能力 | 目的与验收 |
| --- | --- |
| `reset(seed, initialState)` | 可重复构造初始牌局；环境随机与策略随机分流 |
| `observation(seat)` | 只返回本人手牌和合法公开信息 |
| `legalActions(seat)` | 统一枚举出牌、亮倒、碰、各类杠、胡、过；由规则引擎最终验证 |
| `step(action)` | 正确处理摸打与多人响应，返回分数变化和结束状态 |
| 多策略对局调度 | 对比新旧模型，轮换座位，覆盖两家对手的组合 |
| 可重放牌谱 | 记录版本、随机种子、起始牌墙、全部审计动作及结算，可复现异常 |
| 自动报告 | 输出收益差、区间估计、对手分项、行为指标和推理耗时 |

沿用现有 JavaScript 引擎作为唯一规则依据。训练程序即使使用 Python，也先通过批量接口调用同一个模拟环境，避免再复制一套麻将规则。

完整审计牌谱与提供给 AI 的观测分开存放。训练和评测时，策略不能收到真实牌墙、未公开暗手、暗坎身份、对手内部状态或随机种子。改变不可见信息而保持公开历史不变时，策略输出分布应保持不变。

多个模型可以共享学习参数，但同桌三个玩家各自最大化自己的收益，不共享私有手牌、隐藏记忆或协同暗号。

## 3. 主指标与辅助指标

**主指标：每 100 局平均净得分，以底分为单位。**

计算为 `100 × 累计净得分 ÷ 实际局数 ÷ 底分`。默认底分固定为 1，收益包含胡牌、杠分、查叫，不把总收入误当净收入。

升级比较的对象是新旧模型在相同评测条件下的**收益差 Δ**，并同时报告各自绝对成绩。新模型总体赢钱但比旧版少赢，不算提升；面对强对手仍亏分但亏得明显更少，也可能是实质进步。

| 指标 | 用途 |
| --- | --- |
| 净得分及新旧差值、95%区间 | 主要牌技证据 |
| 16 局整桌的累计分、第一/末位率 | 验证完整对局与轮庄影响；并列名次按预定方式分摊 |
| 对各类两对手组合的收益 | 发现相互克制与明显弱点 |
| 胡牌率、自摸率、放炮率、平均胡分 | 解释进攻、防守及做牌倾向，均非越高或越低就一定更强 |
| 杠分、查叫分、亮倒后的净收益 | 检查本地玩法特有决策是否有价值 |
| 大额亏损频率、整桌收益低分位 | 描述风险及稳定性 |
| 推理时间中位数、95%分位、超时率 | 保证牌技提升对应可接受的计算成本 |
| 非法动作、隐藏信息依赖 | 必须为零；发现则判该版本不合格 |

同一个新模型的区间主要描述对局抽样不确定性；要声称某种训练方法稳定有效，还需比较多个独立训练运行，不能只报最好的一次。

## 4. 怎样减小运气的影响

### 4.1 配对牌局与座位平衡

先做独立单局对比：对一个初始牌局，固定手牌、牌墙顺序和庄家，把候选模型、固定对手 P、固定对手 Q 分配到三个座位的 6 种排列都运行。旧版使用相同的初始牌局与对应排列再运行一次。这样一个初始牌局形成一组 12 局的配对实验。

P、Q 可以是两个不同策略，也可以是同一策略的两个独立实例。每个模型都会平衡地拿到三个座位和不同起手；每个配对实验只替换候选席位的新旧版本，另外两家策略保持固定。

策略随机数按实验、座位和策略身份分流，固定对手的随机数不因候选策略额外调用随机函数而错位。记录所有随机源，明确复现范围。

**相同初始牌墙不等于不同策略之后会摸到同一张牌。**碰杠、摸牌次数会改变后续进程，这正是策略效果的一部分。配对只能降低部分方差，不能从单局胜负中精确剥离运气，也不应宣称方差一定减少多少。

### 4.2 完整 16 局对局

单局测试之外，保留真实连庄、轮庄和完整累计分的 16 局评测。新旧模型从匹配的起始条件和分流随机源开始，但后续庄家依据各自真实结果产生，不为了“同牌”篡改轮庄规则。

随机牌流按桌号、局号分流，避免某一版多打几次杠就把下一局的外部随机源全部推移。不同庄家下牌的归属变化如实保留。

发布报告必须包含完整对局结果，不能只在独立单局实验中改进、整桌成绩却明显退步。

### 4.3 区间估计与样本量

以独立初始牌局的整组配对实验，或独立完整对局为统计单位。6 种座位排列相关，不能把它们冒充 6 个独立样本；同桌的每个动作、每一局也不能任意拆开当独立样本。

采用分组、配对的 bootstrap 或等价的合适方法估计 Δ 的 95%区间；按对手组合分层，保留预定权重。涉及多个训练运行时，分别报告对局随机性与训练随机性的影响。

样本量依据预实验得到的配对差方差、预定最小有意义提升及统计功效确定，不以“打一万局必定准确”为标准。可从小规模初筛逐步扩大，但正式发布使用预先固定的预算或有效的序贯统计方案，不能普通区间每隔一会儿检查、恰好变正就停止。

示例仅用于解释，非本项目实测：新版本每百局多得 3 底分，95%区间为 `[1,5]`，有提升证据；估计仍是多得 3 分、区间却为 `[-2,8]`，应报告“证据不足”，不能说两者相等或已经提升。

复杂降方差方法如 AIVAT 可在以后研究，须验证麻将中的适用条件与估计无偏性，不能照搬扑克的效果数字。[AIVAT 原论文](https://arxiv.org/abs/1612.06915)

## 5. 对手池与数据隔离

对手池至少包含：随机合法策略、H0、强化启发式基线、不同攻守倾向的策略、历史强模型，以及专门寻找当前冠军弱点的挑战者。

随机策略用于检查，不能主导冠军排名。三人场必须覆盖“强者+强者”“强者+进攻型”“强者+防守型”等两对手组合，不能只让新旧版各自打两份 H0。训练过程中对手混合可以变化；新旧评测的对手列表和权重必须冻结、可审计。

数据分三层：

1. **训练集**：生成经验、更新模型。
2. **开发验证集**：调参、选择 checkpoint、拟合组合策略；只对该层的结果作开发决策。
3. **封存测试集**：正式检验准备发布的候选模型，包含未参与调参的牌局与对手实例或组合。

评测牌谱不进入训练回放，不使用测试集选择最佳 checkpoint。多次发布后，公开使用过的测试套件仍保留用于回归，同时轮换新的封存测试批次。多个候选或多组“显著提升”声明同时检验时，做适当的多重比较控制。

训练三份同一个模型互打时，三家平均净收益因零和与对称性接近零，这不能作为训练强弱的排行榜。

## 6. 牌技提升路线

### A. 更强且可解释的启发式基线

保留 H0。建立 H1，将目前“优先可亮倒、可杠就杠、能胡就胡、碰后向听改善才碰”的固定选择，改成对未来净收益的估计，首先比较：

- 进张数、活张、等待牌值与成牌速度之间的取舍；
- 不亮倒、立即亮倒的锁手成本、翻倍收益、对手出牌限制与查叫风险；
- 碰、杠、过的费用、听牌变化、连杠和抢杠风险；
- 对未亮倒对手的风险判断，以及已亮倒对手下的合法攻守选择；
- 墙尾、过胡过碰限制、查叫等阶段因素。

用固定预算的模拟或自动参数优化辅助改进，不把 H1 手写偏好当成最终真理。只有实测 Δ 为正，才说 H1 比 H0 强。

### B. 学习整套决策

使用小型策略网络与价值网络，从可解释基线的合法牌谱初始化；若未来有符合本规则的高水平真人牌谱，可另作预训练资料。模仿只作起点，不能把超越老师的希望寄托于无限复制其动作。

输入包括本人手牌、副露、公开弃牌顺序、亮倒与公开听口、可见牌计数、剩余牌数、杠链、本人过手限制、庄家、累计分及剩余局数。历史信息可先用紧凑特征或记忆网络表达，复杂架构由实测收益决定。

输出覆盖出牌、是否亮倒、碰/杠/过、胡/过，不把所有策略选择永久硬编码。动作选择使用合法动作遮罩，规则引擎复验；“同牌多张”的动作按语义映射到合法实体牌，避免学习无意义的手牌索引差异。

以 PPO 作为首个待验证的强化学习基线，便于先建立可复现的训练闭环，不预先认定它会是最终最强算法。[PPO 原论文](https://arxiv.org/abs/1707.06347)

真实奖励以本人结算净分为依据，包含杠分和查叫。局末结算奖励不能漏掉已完成杠；分数跨局正确累计。向听、胡牌次数和牌值可作辅助预测任务，不单独替代目标。若试用中间奖励，需做消融比较，最终不能靠奖励设计掩盖真实收益退步。

### C. 联盟自博弈

对手来自最新模型、历史强者、不同风格模型和挑战者的混合。周期性冻结、交叉对战，既防止遗忘旧策略，又寻找当前冠军的弱点。训练更新与正式评测分开。

至少用数个独立训练随机种子验证有希望的算法；初期建议 3 次，关键结论可扩大到 5 次或更多，数量根据方差和成本确定。可以保留某次训练得到的优秀模型，但报告“一个优秀模型”与“一个稳定有效的方法”是两种证据。

联盟训练借鉴对混合策略学习近似响应的研究思路，三人麻将不据此宣称收敛到全局最优或已经不可被利用。[多智能体策略池研究](https://arxiv.org/abs/1711.00832)

### D. 公开信息推断与有限搜索

在神经策略有稳定收益后，尝试对未知牌分布建模，并在关键决策处作预算受限的模拟搜索：牌型取舍、亮倒、连续杠、残局及查叫。

未知世界只能从本人可见信息出发采样，并满足牌数、公开行动等约束；不能取模拟器里真实对手的手牌作为“猜测”。模拟中的各玩家也应按自己的观测行动，避免用未来全知视角高估某个动作。

搜索与纯策略模型在同一推理时间预算下比较；另列更高预算的性能曲线。不能只给新版更多算力，就把全部差异归因于学习算法更聪明。

麻将强化学习研究如 Suphx 可提供方法参考，但其研究任务与本地卡五星的规则、奖励不同，不直接沿用其成绩、权重或训练规模假设。[Suphx 原论文](https://arxiv.org/abs/2003.13590)

## 7. 多模型如何公平排名与保留

三人场的原始评测结果记录为 `U(候选, 对手P, 对手Q, 座位安排)`，保留完整的三方条件。可以按固定第三家分布汇总成便于阅读的交叉对战表，但不把它当作与第三家无关的两人胜负表。

先用清晰的收益差、分项表与克制关系管理小规模模型池。单个 Elo 分数只作摘要；必要时研究适用于多智能体交互的排名方法，而不是用它替代原始证据。[α-Rank 原论文](https://arxiv.org/abs/1903.01373)

晋级方式：

- **通用冠军**：对冻结综合对手池的收益差，预定的 95%区间下界大于零；提升幅度达到事先约定的实用标准；完整对局和关键对手组合不出现超出预定容忍度的退步；合法性、保密与耗时合格。
- **专家入池**：综合成绩未超越冠军，但在预定细分场景有可靠优势，或扩大了现有策略池能覆盖的对手范围。贴明使用条件，不冒充全面升级。
- **证据不足**：区间跨零，保留候选并按计划增加样本，不改称“差不多强”。
- **淘汰或仅归档**：没有可靠优势、没有新增覆盖面，或在新规则正确性、保密性、时间预算上不合格。

最小有意义提升和退步容忍度在预实验后、正式测试前冻结；例如“每百局 +1 底分”可以作为早期讨论起点，不是客观通用标准。强者阶段可为更小改进增加样本预算，但不能看完测试成绩后临时改门槛。

如果出现多个有价值的强者，先保留少量活跃代表，例如 4—8 个，再按多样性收益与算力调整。组合策略只能读取当下或过去可见信息进行选择；不能看完牌局后挑当局最赚钱的 AI，声称这是实战可用的组合。

## 8. 弱点诊断与持续迭代

每次发现退步，保存可重放局面，分类检查亮倒、危险牌、碰杠、连杠、七对、海底、过手限制和查叫。以公开信息下多个可能世界的反事实模拟估计决策差异，不能因为事后知道真实牌墙，就宣布当时某个动作必错。

逐步建设的对手压力测试只能证明“对已测挑战者的表现”，不能精确计算完整麻将的可被利用程度，更不能声称“不可战胜”。真人盲测和高手复盘可补充新打法与解释，但少量真人对局不能取代统计评测。

学习循环为：测弱点 → 训练或改进 → 开发集筛选 → 封存集检验 → 升级冠军或保留专家 → 更新下一轮训练对手池。

## 9. 算力、里程碑与交付物

当前只确认到本机 CPU 为 i5-12450H、12 个可用逻辑处理器、约 16 GiB 内存；GPU、可用显存与云端预算尚未确定。因此先测吞吐，不承诺训练多少小时达到某个高手等级。

| 阶段 | 交付物 | 进入下一阶段的证据 |
| --- | --- | --- |
| M0：评测基础 | H0 冻结快照、策略接口、固定对手池、配对赛程、牌谱、报告 | 可复现；完整对局通过规则检查；不泄露信息；有吞吐实测 |
| M1：第一轮优化 | H1、相对 H0 的开发与封存测试报告 | 至少取得一个真实提升，或清楚证伪某个改进假设 |
| M2：首个学习模型 | 模仿初始化、PPO 基线、训练曲线、多训练种子记录 | 学习结果经独立比赛验证，不靠训练奖励或复制 H0 证明强度 |
| M3：多强者联盟 | 历史模型池、两对手组合成绩、专家档案 | 通用实力或对手覆盖面持续改善 |
| M4：能力上限探索 | 隐藏牌推断、搜索、组合策略与计算成本对照 | 相同资源下有增益，或额外资源的收益明确 |

先基准测试 1、2、4 个工作进程和批量策略调用，记录每秒局数、每秒决策数、耗时分位和内存，再估计大批量评测与训练成本。训练架构、模型大小、搜索预算、并行数据此选择，云端运行另定资源与费用，不自动开通。

每个候选版本至少留存：规则和代码版本、模型哈希、训练配置与随机种子、训练步数和资源用量、对手池及权重、评测种子清单与协议版本、原始牌谱或重放定位、统计结果和淘汰/晋级理由。

首个应实施的成果是 **M0 的考场和 H0 基准报告**。在它完成前，不把模型文件变大、训练步数增加或偶尔大胜当成牌技提升。

公开项目的借鉴范围、已核实的代码与模型提供情况，另见[公开麻将 AI 与卡五星适配调研](公开麻将AI借鉴与卡五星适配.md)。优先学习 Mortal 的工程与三人分支的表示改造，保留本地规则引擎；PPO、动作价值学习等路线由同条件评测选择，不把其他麻将规则下的模型成绩当作卡五星成绩。

评测方法借鉴强化学习研究对区间估计、多运行与选择偏差的关注；本文件的赛程、指标权重、晋级流程是针对项目提出的工程方案，尚待实测验证。[可靠评测研究](https://agarwl.github.io/rliable/)
