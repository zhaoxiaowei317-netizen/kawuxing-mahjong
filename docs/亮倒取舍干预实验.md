# 亮倒取舍干预实验

独立复验中，旧牌面模型约 46% 的牌局亮倒，新训练版本约 64%，接近 H0；旧模型放炮也更少，但连续净收益优势未被复验确认。这只是相关现象，不能直接认定少亮倒更强。本轮通过替换策略中的亮倒选择，检验其作用，不新增神经网络训练。

## 固定的四个版本

| 版本 | 决定出牌、碰、杠、胡等的基础策略 | 同一张牌的亮倒开关 |
| --- | --- | --- |
| h0-never | H0 | 有合法普通出牌时不亮倒 |
| h0-q-gate | H0 | 用冻结旧模型比较该牌普通/亮倒两个动作的 Q 值 |
| q-h0-gate | 冻结旧模型 | 让 H0 在该牌的两个动作中选择 |
| q-reference | 冻结旧模型 | 保持原版，作为参考 |

所有版本先保留基础策略选定的动作种类和牌张。只有该牌同时允许普通和亮倒出牌时，才改变亮倒标志；只有一个合法动作时直接执行。原模型使用 `tile-q-20261018/model-tiles-offline/epoch-008.json`，在计划中冻结权重和源码哈希。

H0 的原弃牌排序本来就考虑亮倒，h0-never 仍保留这个排序，因此它是“取消亮倒执行”的干预，不能叫作重新优化后的最佳不亮倒策略。q-h0-gate 只允许 H0 比较原模型已选定的那张牌，不能偷偷换成 H0 原本更喜欢的另一张牌。h0-q-gate 使用完整合法动作输入计算 Q，只限制最后的两个动作选择；Q 相同时选普通出牌。

策略改变后会影响后续牌流、轮庄及其他玩家反应。这里测的是整个策略组件替换后的对局净收益，不是某一个孤立局面的无偏动作价值，也不能自动把原模型的全部优势归因于亮倒。

## 固定预算与验收

仅使用 16 手连续对局，H0/H0、H0/greedy-speed 两个对手组合等权，六种座位排列，候选与 H0 分别执行完整轨迹；以完整配对种子组重采样 5,000 次。

- 四个版本各完成开发评测：每对手组合 2 组，每组 16 手，实际 `24 × 2 × 16 = 768` 局，合计 3,072 局。
- 三个干预版本中，只选择开发主指标最高且严格为正的一个；打平按上述表格顺序。q-reference 只作参考，不参与重新选冠军。
- 有候选时，仅该候选接受全新种子的封闭验收：每对手组合 16 组，实际 `24 × 16 × 16 = 6,144` 局。没有候选时不使用封闭种子。
- 总预算最多 9,216 局，不追加牌局争取显著性，不根据封闭结果改策略。游戏默认仍为 H0。

唯一主要检验是固定候选封闭连续对局相对 H0 的净底分差：95% 配对组区间完全高于零才称本批有正收益证据。开发对 H0、开发对 q-reference 的差异、对手子组与行为比例均为未校正多重比较的描述结果。开发每组很少，不能把它的区间当成独立验收。

四个开发版本共用种子，H0 对照应完全一致。实际重复执行计入计算量，不增加独立起手数量。独立单局的表现不在本轮预算中，不能由连续对局结果推断。

## 运行和逐局复核

```powershell
node ai/reveal-study/study.mjs ai-runs/reveal-study-20261019 ai-runs/tile-q-20261018/model-tiles-offline/epoch-008.json
node ai/reveal-study/verify.mjs ai-runs/reveal-study-20261019
node --test tests/ai-reveal-study.test.mjs
```

计划在第一手发牌前写入，冻结原规则、H0、模型、干预、考场和审计源码。已有输出目录拒绝覆盖。每场保存完整牌谱；审计重新发牌，核对初始状态、双方每个动作、轮庄、结算、行为汇总与 bootstrap 结果。

审计还记录：有亮倒开关的决策次数、真正改变基础动作的次数、基础与干预实际宣告次数、胡牌机会及放弃次数，以及按牌谱顺序出现的前 12 个干预局面。这些案例只包含本人手牌、公开状态和所选动作，不读取对手真实暗牌。它们用于理解策略，不是事后挑出的成功案例。
