# AI 评测平台与 M0 验收

日期：2026-10-17。规则 `xiaogan-1.0`，协议 `kwx-paired-v1`。

M0 已实现可运行的考场、冻结的 H0 和开发集基准。本文件记录 M0 阶段的启发式评测；随后已实现并实跑小网络训练，见[训练机制指南](AI训练机制与运行指南.md)。游戏默认电脑仍为 H0，没有引入外部权重。正式晋级要求见[评测方案](AI牌技提升与评测方案.md)。

## 运行和重放

在项目根目录运行，Node.js 24，无新增依赖：

```sh
npm test
npm run ai:eval -- --candidate H0 --incumbent H0 --groups 8 --session-groups 1 --out .tmp/ai-evaluation/check-001
npm run ai:eval -- --candidate H0 --incumbent greedy-speed-v1 --groups 8 --session-groups 2 --out .tmp/ai-evaluation/baseline-001
npm run ai:eval -- --replay .tmp/ai-evaluation/baseline-001/replays.jsonl.gz
npm run ai:benchmark -- --out .tmp/ai-evaluation/throughput-001
```

每次使用新的输出目录，程序拒绝覆盖已有报告或牌谱。评测仅在指定输出目录写文件，不启动桌面服务，不接触 `data/` 或浏览器存档。

`--groups` 是**每个对手组合**的独立起手组数；`--session-groups` 是每组合的连续对局组数。每组包含六种座位安排、新旧两套策略，共 12 个独立单局或 12 桌连续对局。默认每桌 16 局，`--session-hands` 可改；`--bootstrap` 默认为 2000。局数预算在比赛前固定，不因区间变正而提前停赛。

可选策略为 `H0`、`greedy-speed-v1` 和 `random-legal-v1`。随机策略只作通路检查。`greedy-speed-v1` 只按向听选普通弃牌、能胡/杠优先、其余反应过牌，未训练、不主动亮倒，也不碰牌；它是透明的弱基线，不代表高手。

默认对手组合为 `H0+H0` 和 `H0+greedy-speed-v1`，等权。新旧版本只替换候选席位，不能改变两位对手。未来应扩充强对手、历史模型与挑战者，当前对手池不足以代表人类打法。

`--seed` 指定根随机种子；`--split training|development|sealed` 派生互不相同的种子命名空间。封存测试还要求独立提供 `--seed-file`，文件内容是一条非空根种子。命名空间不是访问控制；封存集仍须在流程上隔离，不用于调参。M0 只使用 development，尚未作正式封存检验。

## 文件与接口

| 文件 | 已实现内容 |
| --- | --- |
| `ai/environment.mjs` | reset、白名单 observation、语义 legalActions、step、终局奖励、每步守恒校验、审计重放 |
| `ai/policies/h0.mjs`、`H0.manifest.json` | 当前启发式快照，锁定策略、规则源码及牌型依赖哈希 |
| `ai/policies/index.mjs` | 三种无状态内建策略 |
| `ai/random.mjs` | 评测专用可复现随机源和分流派生；生产发牌仍使用安全随机 |
| `ai/runner.mjs` | 六席位配对赛程、真实轮庄、策略实例隔离、行为/收益/耗时指标 |
| `ai/statistics.mjs` | 按对手分层、整组重采样的 paired bootstrap |
| `ai/evaluate.mjs` | 命令行、JSON/Markdown 报告、压缩审计牌谱及版本存证 |
| `ai/benchmark.mjs` | 同一固定工作负载的 1、2、4 worker threads 吞吐测量 |

策略函数只收到 `(observation, legalActions, policyRandom)`。弃牌动作使用牌种与亮倒标记，环境映射到合法手牌位置；同牌多张不生成重复动作。引擎再次验证动作，非法动作立即失败并保存 `failure.json`，不会悄悄改成其他出牌。

未来有状态策略通过 `runEvaluation({policyFactories:{模型ID:()=>selector}})` 接入；每局每个座位独立实例化，记忆在局内保留、局间重置。若以后需要跨局记忆，应另行版本化协议。自定义模型的权重、编码器与配置也须登记哈希；当前 CLI 只接入内建策略。

H0 使用规则工具函数，但锁定对应源码及 `@kobalab/majiang-core` 版本；任一锁定文件变化会拒绝沿用 H0 标签。新增 H1 应放独立策略文件。规则若修订，需要登记新基线并重跑评测，不能悄悄更新冻结清单后沿用旧成绩。

## 信息与复现边界

观测不包含真实牌墙、对手暗手、亮倒预留暗坎身份或遮挡位置、对手过手/补杠内部标记、手牌索引、未公开的响应和响应收集进度。亮倒明牌规范排序，隐藏部分只给张数；已完成暗杠牌面依据本地规则公开。提供本人手牌/限制、公共听口、副露、弃牌、公开动作记录、剩余牌数、积分和杠链。

观测及合法动作深度冻结，与真实游戏对象分开。已测试：替换不可见牌、暗坎身份、隐藏位置和对手内部状态后，观测、合法动作及 H0 决策不变。策略代码在同一 Node 进程运行，并非恶意代码隔离沙箱；这些是明确的输入边界和已覆盖的不变性测试，不是对任意外部程序的安全证明。

环境随机按组/局号分流，策略随机按座位/角色/策略身份独立分流。整桌真实结果决定下一局庄家；额外开杠不会消耗下一局随机流。相同起手不强迫后续摸到相同牌，行动改变牌的流向照常发生。

牌谱保存起始牌墙、全部请求动作（含过牌）、终局结算、种子、角色分配及规则源码哈希。它是**全信息审计资料，不能当作策略输入**。重放排除仅用于展示的随机战绩 ID 和结束时间，其余结算及玩家状态必须一致。杠分只在终局净收益内结算一次。

`report.json` 保留每个配对组、各组合收益、行为分项、分流种子、硬件/Node、Git 状态、源码哈希、牌谱文件校验和。完整牌谱位于 `.tmp/`，压缩 JSONL 可整批重放；Git 保存报告和一份可独立重放的样例，未保存的本机完整牌谱也可按已记录种子与版本重建。`--replays sample|none` 可减少存储，默认保存 all。

## M0 实测记录

- [同策略零差对照](reports/m0-2026-10-17/null-control/report.md)：432 局，H0 对比 H0，独立单局及 16 局连续对局的 Δ 和区间均为 `[0,0]`；432 份完整牌谱重放一致。
- [H0 开发集基准](reports/m0-2026-10-17/baseline/report.md)：固定预算 960 局，对比透明弱基线，960 份完整牌谱均已重放一致；结果用于描述初始能力，不作为新模型晋级证据。
- [1、2、4 线程吞吐](reports/m0-2026-10-17/throughput.md)：每配置同样 96 局，比较相同种子结果哈希，包含启动、校验和实例回收成本；不等同神经训练吞吐。
- [可重放样例](reports/m0-2026-10-17/baseline/replay-sample.json)：可用 `npm run ai:eval -- --replay docs/reports/m0-2026-10-17/baseline/replay-sample.json` 校验。

H0 对比 `greedy-speed-v1` 的开发集结果如下，分数单位为每百局底分：

| 测试 | 独立配对组/每组合 | H0 均分 | 弱基线均分 | 配对差 Δ | 描述性 bootstrap 95% 区间 |
| --- | ---: | ---: | ---: | ---: | --- |
| 独立单局 | 8 | 14.58 | 18.75 | −4.17 | [−126.07, 113.57] |
| 连续 16 局 | 2 | 16.93 | −46.09 | 63.02 | [57.81, 68.23] |

**这两行都不作为正式显著性或晋级结论。** 单局区间跨零，无法判断 H0 优势；连续对局每组合只有两个独立组，bootstrap 能重采样的情况太少，即使区间全正且看起来窄，也不足以可靠推断未见起手的波动。总共 960 局并不等于 960 个独立样本。下一轮先按所需精度预定更多独立组，不能根据本次正区间直接宣布提升。

同样固定任务的吞吐初测为 1/2/4 线程约 13.32/20.81/26.64 局每秒；这是启发式评测的短测。完整成本与局内牌型影响大，不把这些数字换算成模型训练工期。

全部 119 项自动测试通过，其中新增 22 项覆盖 H0 决策一致、信息边界、非法动作不变性、抢杠双响重放、配对自比、实际轮庄、策略记忆隔离和统计方法。大批对局逐步检查 84 张牌守恒、每种四张及积分零和；这些检查验证考场，不证明 AI 的牌技提升。

当前 bootstrap 区间只描述配对收益差。独立起手的六种座位排列相关，连续桌内 16 局也相关，按整组重采样。连续对局试运行每组合只有少量独立组，区间不能充分代表未见牌局与打法；单组的退化区间尤其不能解释为没有不确定性。

## 接下来如何提升

下一步是建立独立的 H1，先检验亮倒锁手、杠收益和碰牌价值等假设，在开发集筛选后按预定预算进行新封存批次比较。只有长期净分的增益、完整对局和关键组合都符合标准，才更换游戏电脑。

之后再接小型网络、模仿初始化和强化学习，比较多个独立训练种子，并留存能覆盖不同对手的专家。Mortal 的输入、动作遮罩和训练工程借鉴见[具体适配设计](Mortal设计借鉴与M0后续实施.md)；现阶段没有复制外部实现，也没有把其他麻将的权重当成本地高手。
