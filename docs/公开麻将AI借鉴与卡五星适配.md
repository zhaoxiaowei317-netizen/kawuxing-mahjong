# 公开麻将 AI 与卡五星适配调研

核查日期：2026-10-17。适配目标为本项目 `xiaogan-1.0` 规则。本次核对了项目原始说明、论文和部分训练代码，未下载权重、安装项目或复现其性能；“值得借鉴”不代表已经适配完成。

## 结论

有公开的麻将 AI、训练框架和论文值得借鉴。优先研究 Mortal 的训练工程、三人日麻分支的人数适配，以及 Kanachan 的历史信息编码与分阶段学习。

在本次核查的项目中，未发现严格符合本项目已确认卡五星规则、同时提供可核实强度证据的现成模型。现有项目适合提供方法和工程参考，卡五星策略仍须在本项目环境下重新训练、评测。

## 主要候选

### 2026-10-19 的本地落地进度

已新增独立实现的 `ai/tile-q/` 路线：残差卷积牌面编码、合法动作遮罩下的 dueling Q、完整蒙特卡洛收益回归、离线 CQL、辅助顺位预测，以及当前模型与固定/历史对手继续对战采样。它参考 Mortal 的公开方法，保留本项目卡五星规则，没有复制 Mortal 源码或导入日麻权重。

这与最初的通用 PPO 基线、后续的单次前瞻筛选器属于不同路线。新模型覆盖每个需要选择的合法动作，包含出牌、亮倒、碰杠、胡和过；同时保留已有公开牌效输入，另设关闭卷积分支的同数据对照。具体结构、损失、适配差异与验证方式见[牌面卷积与动作价值学习](牌面卷积与动作价值学习.md)。

Meowjong 的五网络方案、Kanachan 的历史序列模型、Suphx 的全局奖励预测与 oracle guiding 尚未复现。不能把“已有收益标签”称为完成 Suphx，也不能把本地紧凑网络等同于原版 Mortal。

### 原始候选核查

| 项目 | 核实到的公开内容 | 对卡五星的价值与边界 |
| --- | --- | --- |
| [Mortal / 凡夫](https://github.com/Equim-chan/Mortal) | 四人日本立直麻将；Rust 模拟器、Python 训练与推理代码；项目说明为 AGPL-3.0 | 优先读其批量模拟、模型、训练和评测结构；规则及输出编码需改造，原版日麻模型不能直接视为卡五星高手 |
| [mortal-sanma](https://github.com/Mateces/mortal-sanma) | Mortal 的三人日麻分支；README 列明 108 张、禁吃、拔北及三人观测和动作编码；AGPL-3.0 | 比四人版更接近三人流程，可研究四改三的方法；仍非本项目 84 张卡五星，其性能与验证声明需独立复核 |
| [Kanachan](https://github.com/Cryolite/kanachan) | 四人日麻框架、牌谱标注、训练程序、token/序列表示和分阶段学习；明确不提供训练数据、训练好模型 | 适合借鉴时序信息和训练组织；不能当作下载即用的高手，也不先假设大模型路线适合本机资源 |
| [Meowjong 论文](https://arxiv.org/abs/2202.12847) | 三人日麻研究；分别处理弃牌、碰、杠、拔北、立直，以预训练和自博弈增强 | 对三人不完全信息决策的任务拆分有参考价值；论文中动作集合与卡五星不同，本次未核实可直接采用的完整训练发布物 |
| [北大国标麻将竞赛项目](https://github.com/ailab-pku/Chinese-Standard-Mahjong) | 国标麻将的裁判、算番工具和样例 bot | 可研究对局协议、工具和竞赛设计；它是竞赛资源，不能把样例 bot 当作已验证强者；国标规则不同 |
| [Suphx 论文](https://arxiv.org/abs/2003.13590) | 深度强化学习、全局奖励预测等研究方法 | 借鉴长期收益学习思路；其日麻成绩不能外推为卡五星成绩，本次未核实官方可直接复用的完整训练代码与权重 |

Mortal 的官方文档说明其兼容天凤四人规则，并提供 Rust 模拟器与 Python 接口。[官方文档](https://mortal.ekyu.moe/)

Mortal 当前公开 `mortal/train.py` 使用动作价值网络、蒙特卡洛回报目标，离线阶段有 CQL 正则及下一顺位辅助预测。它不是先前方案中暂定的 PPO 路线；两者都只是可比较的候选方法，不能把“学习 Mortal”理解成照搬一种既定算法。[训练源码](https://github.com/Equim-chan/Mortal/blob/main/mortal/train.py)

## 还需要区分代码、模型和数据

- 公开训练代码不等于提供原作者最强权重，也不等于附带训练数据。Kanachan 的 README 明确说明数据和训练好模型由用户自备。
- Mortal 的 README 将权重问题指向作者的独立说明，不把其公开仓库理解为随附官方最强模型。[项目说明](https://github.com/Equim-chan/Mortal)
- [MahjongAI-Sanma-Training](https://github.com/Gandhara2077/MahjongAI-Sanma-Training) 提供三人日麻训练工作流，其说明明确将在线路径标为实验功能，外部权重不入库；可参考编排，但不据此认定已有可直接迁移的强模型。
- [mj_ai](https://github.com/yuanfengyun/mj_ai) 可参考概率估计思路，其 README 明确说明局部估算部分尚未加入字牌和吃碰杠判断，不适合作为卡五星完整强 AI。

本项目现有 `@kobalab/majiang-core` 已提供牌型拆解及一般向听等底层工具，七对向听已按本地四张算两对的规则适配。下一阶段主要欠缺的是强决策、训练和独立评测，而非再换一套外部算番器。

## 必须适配的内容

| 范围 | 本项目要求 |
| --- | --- |
| 牌张及表示 | 21 种、84 张，筒条中发白；不能只删除日麻模型的几个输出就当适配完成 |
| 玩家与座位 | 三人固定，按已确认轮庄规则运行，不能把第四家补空状态后默认模型有效 |
| 观测信息 | 本人手牌、公开行动、亮倒听口、可见牌、暗坎遮罩及本人的过手限制；不得读真实暗手 |
| 动作 | 不吃；亮倒与弃牌组合、碰、各类杠、抢杠响应、胡和过；合法性由当前引擎验证 |
| 亮倒与避炮 | 亮倒后的锁手、公开信息、收付款倍数、宣告即生效以及强制避炮等都要进入环境与编码 |
| 牌型与杠链 | 卡五星、四归最后胡到第四张、七对四张计两对、连杠费用与胡分递增等按本地规则处理 |
| 奖励 | 净得分包括胡分、杠分和查叫，胡分单笔 16 倍封顶；不能直接用日麻役种、段位点和顺位奖励 |
| 训练样本 | 主要使用本地规则生成经验，合法取得的同规则高水平真人牌谱可补充；日麻动作标签不直接当卡五星标准答案 |
| 对战成绩 | 改造后再进入固定考场；日麻段位、复盘相似度或作者自报胜率不换算为卡五星强度 |

这些差异意味着：现成权重的直接适用性低；从公开项目中借鉴训练框架与算法的价值较高。能否迁移部分编码器参数、是否比从零训练省算力，需要做对照实验，不能提前承诺。

## 建议采用方式

1. 继续完成评测平台与 H0 基线，保证所有候选使用同一套卡五星规则和信息边界。
2. 优先读 Mortal 的训练、批量对战及数据管线，研究三人分支改了哪些玩家相关编码；暂不替换本地规则引擎。
3. 首个学习模型保持紧凑，使用卡五星输入与动作设计，从本地经验训练。将 PPO 自博弈作为可运行基线；有合适数据后，再比较 Mortal 风格的价值学习、离线正则与在线改进。
4. Kanachan 的历史序列编码、Meowjong 的任务拆分、Suphx 的长期收益预测作为后续可独立消融的研究方向，不一次全部叠加。
5. 对权重初始化、网络结构及训练方法做相同资源预算下的对照，根据封存评测的收益差决定保留哪些版本。

正式引入任何外部代码前，锁定提交版本，核对其代码、数据及权重各自的许可与来源，并跑本项目规则回归与信息保密测试。此阶段未引入外部源码或模型，规则引擎、现有电脑策略均未因本次调研发生改变。
